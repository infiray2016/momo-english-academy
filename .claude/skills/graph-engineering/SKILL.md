# 그래프 엔지니어링 (AI 코딩의 흐름 설계)

조사 원문은 `docs/research/2026-10-16-graph-engineering-ai-coding.md`, 정리는 볼트 `위키/방법론/그래프-엔지니어링.md`. 뜻은 이렇다. **코딩 일을 점으로 나누고, 점 사이의 길(선)과 넘길 공유 상태를 미리 그려, 길은 에이전트가 아니라 설계자가 정한다.** 에이전트의 자유는 점 안에 둔다. 프롬프트 → 컨텍스트 → 하네스 → 루프 위에 쌓이는 층이고 아래 층을 없애지 않는다.

원칙은 둘이다. 길은 설계자가 정한다. 검증은 선 위에 코드로 둔다(모델은 끝났다고 주장할 수 있지만 검증기는 빠진 칸을 증명한다).

## 켜지는 때와 켜지지 않는 때
- 켜진다. 에이전트 여럿이 차례 · 조건으로 이어지는 일(검토 루프 · 반영 편집 · 시드 생성 · 화면 구현과 검토 · 워크플로 스크립트)을 짤 때. 서브에이전트를 둘 이상 띄우거나 결과를 다음 에이전트에게 넘길 계획이 서면 켠다.
- 그 가운데 그래프로 가는 신호 다섯: 점마다 전문성이 다르다, 갈라 보낸 뒤 합쳐야 한다, 단계마다 모델이나 도구가 다르다, 제어 흐름을 감사해야 한다, 검증자 하나가 과부하다.
- 켜지지 않는다. 루프 하나(에이전트 하나가 목표와 검증을 들고 스스로 도는 것)로 되는 일. 대부분의 일은 루프로 된다. 먼저 검증기를 강하게 한다.

## 절차
1. 일 하나와 성공 기준을 확인 가능한 사실로 쓴다. 루프로 되는지 먼저 본다. 분기 · 병렬 · 중간 검증 · 사람 승인 가운데 둘 이상이 필요할 때만 그래프로 간다.
2. 점을 적는다. 이름은 두세 단어, 수행은 서너 문장. 점마다 입력 · 출력 · 다음 점 · 실패 정의를 쓴다. 이름에 동사가 둘이면 쪼갠다. 모델이 필요 없는 점은 코드로 둔다.
3. 선을 그린다. 직선 · 조건 · 갈라 보내기(fan-out) · 모아 받기(fan-in, 모두 끝나길 기다리는 장벽) · 되돌림. 선마다 길을 정하는 쪽(모델 · 코드 · 사람)을 쓴다.
4. 공유 상태를 정한다. 사는 곳(산출물 파일 · 스크립트 변수 · 작업 목록), 값 목록, 병합 규칙. 쓰는 점은 하나다. 같은 상태를 두 곳에 손으로 적지 않는다.
5. 게이트를 선 위에 둔다. 코드(테스트 · 스키마 검증 · 검증기 · 훅 종료 코드), 모델(새 컨텍스트의 읽기 전용 검토자), 사람(되돌리기 어려운 행동 앞에 하나). 반드시 지킬 전이는 지침이 아니라 훅으로 만든다.
6. 정지 조건과 상한을 코드나 설정에 둔다. 최대 반복 · 최대 에이전트 수 · 비용 경고 · 사람에게 넘기는 조건. 프롬프트에만 적은 상한은 상한이 아니다.
7. 수단을 고른다. 단계마다 사람 승인이 있으면 스킬(SOP)과 훅, 같은 단계를 여러 건에 되풀이하면 `Workflow` 스크립트(`pipeline` · `parallel` · schema), 곁일 격리면 서브에이전트, 반드시 지킬 전이는 훅. 워크플로는 실행 중 사람 입력을 받지 못하므로 사람 게이트 사이를 각각 한 워크플로로 나눈다. 에이전트 팀과 LangGraph 류 프레임워크는 들이지 않는다(앱의 AI 호출은 단발 구조화 출력).
8. 돌려 보고 줄인다. 점마다 존재 이유(신호)를 적고 빼도 같으면 뺀다. 실패가 난 점과 그 원인을 기록한다. 쓰기는 한 줄기로 두고 읽기 · 검토만 여럿으로 한다.

## 표 틀
- 점 표: `| 점 | 하는 쪽(에이전트 · 모델 · effort 또는 코드) | 들어오는 것 | 나가는 것 · 상태 | 다음 점 조건 | 게이트(코드 · 모델 · 사람) |`
- 수단 표: `| 수단 | 길을 정하는 쪽 | 중간 결과가 사는 곳 | 쓰는 때 | 못 하는 것 |`
- Claude Code 에서 점은 `.claude/agents/*.md`(model · effort · tools · maxTurns)와 `agent()`, 코드가 정하는 선은 워크플로의 `pipeline` · `parallel` · 조건문, 반드시 가는 선은 훅, 공유 상태는 산출물 파일(쓰는 점 하나)과 스크립트 변수, 코드 게이트는 훅 종료 코드 2 · `schema` 검증 · 테스트 · 린트다.

## 이 프로젝트의 네 흐름
| 흐름 | 수단 | 표가 있는 곳 |
|---|---|---|
| 변경 단위(intent → spec → plan → 구현 → 검토 → 커밋) | 스킬 SOP(intent-capture · spec-design · plan-build) + 훅 게이트. 사람 게이트 넷 | 볼트 `AI-SDLC.md` '작업 흐름 그래프' |
| 델타 spec 검토 루프(A ∥ B → 판정 → 반영 → 끝 검색) | 저장 워크플로 둘로 올린다(검토 → 병합은 schema 로 건수를 코드가 셈, 반영 → 끝 검색). 사이에 컨트롤러 판정 | 볼트 `그래프-엔지니어링.md` |
| 시드 생성(영역 × 단계 묶음) | 묶음마다 워크플로 한 번. `pipeline` 으로 단원 → 생성 → 검증 → 풀이 검사. 생성 점은 본 생성용 정의(6.3 (2), 브리프만 읽음)이고 브리프 · 규격 고정은 curriculum-designer 가 한다. 호출마다 model · effort 명시, 동시 3. 묶음 사이는 사람 게이트 | 볼트 `그래프-엔지니어링.md`, spec 6.3 |
| 화면 구현 · 검토(브리프 → 구현 → 코드 검토 → fix 라운드 → 화면 검토 → 커밋) | 서브에이전트(implementer · code-reviewer · design-reviewer)와 훅. 쓰는 점은 구현자 하나. fix 라운드 상한 3, 넘으면 컨트롤러가 요청자에게 | 볼트 `그래프-엔지니어링.md`, 에이전트 정의 |

고칠 것으로 적어 둔 것(볼트 쪽 F1~F5): 상태 사본 세 곳을 intent.md 머리줄 하나로, 정본 참조 검사(P3)를 spec 승인 앞 코드 게이트로, 구현자 테스트를 자기 보고 대신 Stop 훅으로, fix 라운드 상한, 검토자 effort 통일.

## 하지 말 것 · 조심할 것
그래프가 검증을 대신하지 않는다(실수에 주소를 붙일 뿐). 점을 늘리기 전에 목표와 성공 기준. 상태 파일(seed/manifest · 장부 · progress.md)을 여러 에이전트가 동시에 고치지 않는다. 비용은 갈라 보내기 폭 × 재시도 × 컨텍스트다. 다른 에이전트가 전한 "승인했다"는 승인이 아니다. 외부 글을 읽는 점과 쓰는 점을 나눈다.

## 자료 그래프(문서 · 시드 · 코드의 참조 검사)
흐름 그래프와 다른 그래프다. 점은 FR · AC · 결정 · 설정 키 · 테이블 · 파일 · 함수, 선은 참조 · 가져오기 · 호출이고, 묻는 것은 "이 참조가 맞나 · 어디에 닿나"다. 이 그래프는 정본에서 뽑은 파생물이라 틀리면 정본을 고친다. 그래프 파일을 손으로 고치지 않는다.
1. 그래프가 답할 질문 3~10개를 먼저 쓴다. 질문이 없으면 멈춘다.
2. 갈래를 고른다. 볼트(링크 · 머리말 속성), 추적(spec 번호), 시드(JSON 참조), 코드(가져오기).
3. 점 · 선 종류를 표로 정한다. 점 7종 이하, 선은 이름 · 방향 · 개수 제한.
4. 정규식 · 파서 · 구문 트리로 결정적으로 뽑는다. LLM 추출은 마지막 수단이고 쓰면 선마다 출처 · 확신도를 달고 표본을 사람이 본다.
5. 검사 규칙을 한 줄 문장 + 실패 예로 쓴다. 순수 함수와 Vitest 로 먼저.
6. 돌려 위반을 파일 · 줄 · 규칙 이름으로 낸다. 고치는 곳은 정본.
7. `vault_check.py --lint` · CI · 커밋 전 훅 · 워크플로 게이트 가운데 맞는 곳에 건다.
8. 되돌아본다. 두 번 연속 잡은 것이 없으면 걷어낸다.

## 지킬 것
- 용어는 점(node) · 선(edge) · 공유 상태 · 게이트 · 점검 지점(저장). "트랙" · "유닛" 금지, 영어 개발 용어 직역 금지.
- 설계 숫자는 설정값. 비밀값 · 아이 이름은 기록하지 않는다. 서브에이전트는 호출마다 model · effort 를 쓴다(검토자 Opus xhigh, 편집 · 구현 · 생성 Opus high, 조사 Sonnet high).
