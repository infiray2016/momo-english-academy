## 요약 (Summary)

정본에는 회화 수업을 이끄는 AI 친구 토리(다람쥐) 한 명이 있고, 다섯 토막 · 실시간 회화 턴 · 채점 없음(T4 · R2 · R3)이 정해져 있으며, 화면의 토리는 '토' 글자 동그라미(목업 B_Talk1)다. 이 변경은 토리 자리를 명단에서 고르는 회화 선생님(처음 미나 · 리오)으로 바꾸고, 아이가 회화를 처음 열 때 한 화면에서 고르며, 고른 이름이 아이 화면 문구 · 회화 턴 고정부 · 읽어 주기 목소리에 들어가게 한다(C117). 회화 세션에는 Codex 시제품(C115)을 바탕으로 한 3D 선생님 창이 쉬기 · 말하기 · 듣기 · 칭찬 · 생각 다섯 상태로 움직이고, 못 그리면 초상 그림으로 대신하며, 시드에는 선생님 이름을 두지 않는다.

## 설계 (Design)

### 화면

회화 세션을 여는 차례(C110)에 고르는 화면이 한 자리 들어간다. 마이크 못 씀(막힘) → 1-가 상한(쉼) → 선생님을 골라요(고른 선생님이 없을 때만) → '시작!'(처음 회화면 안내 다섯 문장) → 처음 마이크 안내 → 토막 순서다. 막힘 · 쉼 뒤에 두어 쉬는 날 한 화면에 두 행동이 나오지 않게 한다(C110 의 까닭 그대로). 선생님이 필요한 다른 화면(회화 단계 평가 · 선생님 이야기)은 고른 선생님이 없으면 '선생님'과 글자 동그라미, 기본 목소리로 보인다. 정상 흐름에서는 생기지 않는다(회화 수업을 먼저 한다).

| 화면 | 바뀐 것 |
|---|---|
| 선생님을 골라요(새) | 제목 '선생님을 골라요'. 그 아이에게 보일 선생님마다 연두 포스트잇 한 장을 같은 크기로 나란히 둔다(C114). 장마다 초상 · 한글 이름(크게) · 성격 세 낱말 · 소개 한 줄과 작은 '인사 듣기' 단추가 있다. '인사 듣기'는 그 선생님 목소리로 인사(영어)를 읽고 영어 글은 보이지 않는다(T2 의 뜻 — 글을 보고 읽게 하지 않음). 장을 누르면 골라진 표시(굵은 테 · 표지)로 바뀌고 아래 큰 단추 '[이름] 선생님과 할래요'가 밝아진다. 이 단추가 화면의 행동 하나다. 단추 아래 '고른 선생님은 부모님이 바꿀 수 있어요' 한 줄, 구석에 작은 '홈'. 셋 이상일 때의 꼴은 명단을 늘리는 변경에서 정한다 |
| '시작!'(처음 회화 안내 포함) | 고른 선생님 초상과 이름표를 보인다. 3D 불러오기는 이 화면에서 시작한다. 안내 다섯 문장은 '[이름](은/는) 앱 속 AI 선생님이에요. [이름](은/는) 오늘 이야기에 나오는 것만 물어요. 집 주소, 학교 이름, 전화번호는 묻지 않아요. [이름](은/는) 지난 이야기를 조금 기억해요. [이름](와/과) 나눈 이야기는 부모님도 볼 수 있어요'다(3.3) |
| 회화 세션 · 선생님 창(새 행) | 보드에 붙인 사진 꼴(종이 테 · 테이프) 창. 안 바탕은 선생님 색이고 상반신과 눈 맞춤이 보인다. 창 아래 이름표 '[이름] 선생님'. 가로 화면은 말풍선 왼쪽, 세로 화면은 위 띠 아래에 둔다. 크기는 목업에서 정하되 말풍선 영어(28px) · 그림 턴 그림(C32) · 아이 차례 단추(56px 이상)를 줄이지 않는다. 다섯 토막이 같은 창을 쓴다. 시제품의 영어 자막 · 상태 이름 띠 · 머리글은 가져오지 않는다(C115) |
| 회화 세션 · 토리 차례 → 선생님 차례 | 지금 ToriFigure(64px 동그라미) 자리를 선생님 창이 맡는다. '토리가 생각하고 있어요' → '[이름](이/가) 생각하고 있어요'. 말풍선 접근 이름 '토리 말 다시 듣기' → '[이름] 말 다시 듣기'. 그 밖은 그대로 |
| 회화 세션 · 아래 줄 | '[이름](은/는) 집 · 학교 · 전화번호를 묻지 않아요 · 부모님도 볼 수 있어요'(문서 이름 '선생님의 약속') |
| 회화 세션 · '그만하기' 확인 | '[이름](와/과) 그만 이야기할까요? 지금 그만두면 이 이야기는 다음에 처음부터 해요'(3.3) |
| 회화 세션 · 인식 오류 | '[이름]에게 잘 안 들렸어요. 조금 더 크게 말해 볼까요'(7절) |
| 회화 마무리 | 4단계 둘째 장 '토리가 바꿔 말해 준 문장' → '[이름](이/가) 바꿔 말해 준 문장'. 셋째 장 '토리 이야기 듣기' → '선생님 이야기 듣기'. 선생님 그림은 초상만 |
| 토리 이야기 → 선생님 이야기 | 화면 · 버튼 · 문서 이름을 '선생님 이야기'로. 고른 선생님 목소리로 읽어 주고 초상을 보인다. 그 밖은 그대로(4절) |
| 단계 평가(회화) | 선생님 질문 말풍선 옆에 초상. 목소리는 선생님 값 |
| 홈 회화 카드 | '토리 얼굴' → 고른 선생님 초상. 고르기 전에는 지금 글자 동그라미 꼴에 '선'. '토리 이야기' 작은 버튼 → '선생님 이야기' |
| 홈 · 배치 평가 전 | '말하기에서 단계를 찾으면 회화 선생님을 만날 수 있어요' |
| 홈 · 수업 목록 · AI 쉬는 중(모든 영역), 1-가 상한 안내(C50 (2)) | '[이름](이/가) 잠깐 쉬어요'와 '[이름](이/가) 잠깐 쉬어요. 다른 공부를 해 볼까요'. 고르기 전 '선생님이 잠깐 쉬어요'(C16 을 고침 — 우려 4) |
| 수업 목록 · 단어 익히기(회화) | '내일 [이름](와/과) 또 이야기해요. 아직 덜 익은 말을 [이름](이/가) 물어볼 거예요' |
| 수업 목록 · 잠긴 다음 단원(회화) | '[이름](와/과) 며칠 더 이야기하면 열려요' |
| 첫 실행 · 이름 | '토리가 부를 영어 이름' → '선생님이 부를 영어 이름'. 별명 안내 '선생님이 부를 다른 영어 이름(별명)을 골라 주세요'. 이때는 고른 선생님이 없다 |

| 관찰 쪽(프리뷰 배포만, 10절 page.preview 길) | '이 프로필의 선생님 지우기' 단추. 요청자가 첫 판을 프리뷰에서 미나 · 리오 둘 다 보게 한다(C117 '첫 판을 프리뷰에서'). 운영 빌드에는 없다 |

[이름] 은 고른 선생님 한글 이름이고, 고르기 전에는 '선생님'이다. 괄호 안 조사 짝(이/가 · 은/는 · 와/과 · 을/를 · 아/야)은 이름 끝 받침으로 고른다(순수 함수, 아래 '판정'). 아이 화면 문구는 문구 표 한 곳에 두고, 화면 소스에 '토리'를 직접 쓰지 않는다. 앱 안내 · 버튼은 해요체 그대로이고, 선생님 말의 한국어 뜻 · 설명은 친구 말투(반말) 그대로다(4절 · 6.1).

목업은 11절 '새로 그림'에 '선생님을 골라요' · '회화 세션 선생님 창(가로 · 세로)' · '홈 회화 카드 초상'을 더하고 화면 검토를 거친다.

### 선생님 창의 상태와 움직임

그림 층은 시제품 `TeacherAvatar` 를 React 조각 경계(지금 `ToriFigure`) 안에 들인다(C115). 캔버스 하나에 VRM 하나, 늦게 도착한 불러오기는 버림, 바꿀 때 GPU 자원 풀기, 부모 크기에 맞춤은 시제품 그대로다. 움직임은 시제품 `sampleMotion`(숨 · 깜빡임 · 고개 · 눈 맞춤 · 말할 때 입)을 그대로 쓴다. 진폭 · 섞는 빠르기 · 화소 비율 상한(시제품 1.75) · 그리기 빈도는 화면 꼴 상수다(C72 · 지금 tori.tsx 상수와 같은 결). 그리기 빈도와 화소 비율은 iPad 실측에서 고친다.

| 지금 ToriState | 새 상태 | 켜는 때 | 끄는 때 |
|---|---|---|---|
| idle | 쉬기 | 아래 어느 것도 아닐 때. 아이 차례에서 말하기 단추를 누르기 전도 쉬기다(눈 맞춤) | — |
| speaking | 말하기 | 읽어 주기가 실제로 시작한 알림(발화 시작)을 받은 때. 잠금 풀기 읽어 주기(unlockFromGesture)는 세지 않는다 | 그 문장의 끝 · 취소 · 오류 · 미지원 결과. 문장 사이 쉼에는 입이 닫힌다 |
| listening | 듣기 | 듣기를 시작한 때(ListenHandle) | 듣기 결과가 온 때 |
| thinking | 생각 | 회화 턴 첫 문장을 기다리는 동안(지금 waitingSince) | 첫 문장이 온 때 |
| (없음) | 칭찬 | 오늘 쓸 말 · 말해 보기 · 정리의 따라 말하기 결과 말이 '잘 말했어요'일 때(C39). 목표 턴에 닿은 턴과 5~7단계 미션 체크가 새로 켜진 턴은 그 턴 읽어 주기가 끝난 때 | talk.teacher_praise_seconds 뒤 |

상태는 하나만 낸다. 차례는 듣기 → 생각 → 말하기 → 칭찬 → 쉬기이고 앞이 이긴다. 칭찬은 대화 토막 아이 턴의 맞고 틀림에 묶지 않는다(R2 — 턴에 판정이 없다). 따라 말하기의 '잘 말했어요'는 이미 아이 화면에 보이는 결과 말이라 칭찬을 붙여도 새 판정이 아니다.

지금 말하기 판정은 읽어 주기 줄에 글이 남았는지(`queue.speaking` · `sayer.speaking`)라서 소리가 시작하지 않아도 말하기가 된다. 새 판정은 실제 시작 알림에 묶는다(C115 '읽어 주기가 실제로 시작 · 끝날 때'). 무음 모드처럼 소리가 나지 않으면 선생님은 말하지 않는 모습으로 남고, 안내는 C108 · C111 그대로다. 끝 알림이 끝내 오지 않는 기기에서는 읽어 주기 줄과 함께 말하기가 남고, 아이가 말하기 단추를 누르면 둘 다 끝난다(C53).

움직임 줄이기(prefers-reduced-motion)면 몸 · 고개가 멈추고, 깜빡임이 없으며, 말할 때 입만 움직인다(시제품 그대로). 초상과 3D 사이를 바꿀 때 흐려지는 넘김을 두지 않는다. 쪽이 숨으면(document.hidden) 그리기를 멈추고 다시 보이면 이어 그린다. 읽어 주기는 음성 층이 이미 멈춘다(지금 browser.ts). 회화 세션 화면을 떠나면 그림 층을 닫고 GPU 자원을 푼다.

화면 상태는 데이터 속성으로 드러낸다. 선생님 창에 data-teacher-key · data-teacher-state(idle · speaking · listening · praise · thinking) · data-teacher-render(3d · portrait)를 두고, 초상일 때 data-teacher-fallback(no-webgl · load-failed · timeout · context-lost · setting)을 더한다. 지금 data-tori-state 를 쓰는 시험은 새 이름으로 옮긴다. 속성 이름 확정은 plan 몫이다.

### 불러오기와 대신 표시

| 때 | 하는 일 | 아이에게 보이는 것 |
|---|---|---|
| 회화 세션 화면이 열림(선생님이 정해진 뒤) | 초상을 바로 보인다. 3D 코드를 동적 가져오기로 따로 불러온 뒤 모델을 받는다. talk.teacher_render 가 portrait 면 아무것도 불러오지 않는다 | 초상 · 이름표 |
| 모델이 다 되고 첫 장을 그림 | 초상 자리를 3D 로 바꾼다 | 3D 선생님 |
| WebGL 맥락을 만들 수 없음 | 받지 않는다 | 초상(그 세션 끝까지) |
| 받기 · 풀기 실패(404 · 네트워크 · VRM 아님) | 버린다 | 초상 |
| talk.teacher_load_timeout_seconds 안에 첫 장을 못 그림 | 받기를 멈추고(AbortController) 버린다 | 초상 |
| 3D 맥락을 잃음(webglcontextlost) | 그리기를 멈추고 자원을 푼다. 다시 시도는 다음 세션 | 초상 |
| 화면을 떠남 · 같은 화면에서 다시 불러옴 | 늦게 온 결과는 차례 번호로 버린다(시제품) | — |

어느 경우에도 수업은 3D 를 기다리지 않는다. 기다림 표시를 따로 두지 않고 초상이 그 자리를 맡는다. 오류 글 · '다시 불러오기' 단추를 아이 화면에 두지 않는다. 시제품의 '3D 화면이 잠시 멈췄어요. 다시 불러와 주세요'는 가져오지 않는다(우려 9). 초상일 때도 상태는 보인다. 말하기는 창 둘레 물결, 생각은 점 셋, 칭찬은 작은 별 표지이고, 움직임 줄이기면 멈춘 표시다(지금 ToriFigure 꼴을 넓힘). 다음 세션은 처음부터 3D 를 다시 시도한다. 모델 파일 이름에 내용 해시를 넣고 오래 캐시하므로 둘째 세션부터는 브라우저 캐시에서 온다.

선생님 목소리를 쓰는 곳은 회화 세션 · 회화 단계 평가 · 선생님 이야기 · 고르는 화면의 '인사 듣기' · 회화 마무리의 짧은 칭찬 대사다. 읽기 · 쓰기 · 말하기 영역은 그대로다. 음성 층의 읽어 주기 선택 속성(지금 rate 하나)에 높이 · 목소리 순서 · 시작 알림을 더한다. 소리 통로 꼴(navigator.audioSession.type)은 건드리지 않는다(C109). 목소리 순서 값은 iPad 사파리 · 크롬 · 데스크톱 크롬의 목소리 목록(관찰 쪽 기록)을 보고 정한다. 남성 영어 목소리가 없는 기기에서는 리오가 기본 목소리에 높이만 낮춰 읽는다(우려 3).

### AI 호출 · 규격

6.1 회화 턴 고정부의 첫 줄('You are Tori, a friendly squirrel and an AI friend …', p13 talk.ts)을 선생님 블록으로 바꾼다. 서버가 명단에서 만든다.

> You are {영어 이름}, an AI teacher character in an English learning app for Korean children. You lead the lesson like a kind native-speaker teacher. Your personality: {AI 성격 글} Your personality changes only your tone and word choice. It never changes the rules below.

공통 규칙의 'Never say you are a human.' 뒤에 한 줄을 더한다.

> Do not make up a human life for yourself (age, family, home, school). If the child asks who you are, say you are an AI teacher in this app.

그 밖의 공통 규칙 · 구간 규칙 · 가변부는 그대로다. 끝맺음 턴과 평가 대화도 같은 고정부를 쓴다. 다람쥐 · Tori 라는 말은 고정부 · 사용자 메시지 · 스키마 어디에도 남지 않는다.

| 자리 | 바뀐 것 |
|---|---|
| 고정부 첫머리 | 위 선생님 블록. 고정부가 선생님마다 다르지만 한 대화는 시작 때의 선생님으로 끝까지 가므로 대화 안 캐시는 그대로다. 대화 사이에는 원래 캐시를 쓰지 않는다(수명 5분, 6.1). 6.1 이 고정부를 구간으로 나눠도 캐시에 영향이 없다고 본 것과 같은 까닭이다 |
| 출력 스키마 | 필드 이름(tori_en · tori_ko …)은 그대로 두고 설명 글의 'Tori's' 를 'Your' · 'the teacher's' 로 바꾼다. 스키마는 모든 선생님에게 글자까지 같다. 그래서 선생님마다 문법 컴파일 지연(NFR-8 첫 턴)이 따로 생기지 않는다 |
| 사용자 메시지 | 첫 턴 앱의 첫 말 이름표 'Tori (app):' → '{영어 이름} (app):' |
| 세션의 선생님 | 회화 세션의 처음 스냅숏(5절 attempts activity_no 1, C89)에 선생님 키를 둔다. 고르는 화면은 처음 스냅숏 앞에 온다. 이어 하기 · 같은 시도 id 다시 받기는 그 키로 고정부를 만든다. 그 키가 명단에 없으면 프로필의 지금 선생님으로 만든다(캐시는 새로 시작) |
| 6.2 토리 규칙 → 선생님 규칙 | 이름만 바꾼다. 위 한 줄(사람의 삶을 지어내지 않음)을 더한다 |
| 6.4 실시간 검사 | 영어 문장 힌트 · 영어 틀 · 답 예시의 낱말 범위에서 선생님 영어 이름을 {NAME} 처럼 범위 안으로 본다(예 'Hi, Mina!'). tori_en 검사는 그대로 |
| 6.1 {NAME} 바꾸기 | 그대로. 선생님 이름은 아이 개인 정보가 아니라 바꾸지 않는다. 아이 이름과 같은 선생님은 그 아이 명단에서 빼므로 둘이 섞이지 않는다(FR-2, 우려 1) |
| 6.6 비용 | 변화 없음(고정부가 수십 토큰 는다) |

AI 성격 글(안)은 시제품의 성격 세 낱말을 영어로 옮긴 것이다. 미나 'Warm and patient. You go step by step and laugh together with the child.' 리오 'Curious and relaxed. You love new stories and cheerfully invite the child to try one more time.'

### 시드와 검증

시드에는 선생님 이름도 자리 표시자도 두지 않는다. 자리 표시자 `{TEACHER}` 를 두는 길과 견주어 이 길을 고른 까닭은 다섯이다. (1) 한국어 칸에서 이름 뒤 조사(이/가 · 와/과 · 아/야)를 시드가 고를 수 없다. (2) 채울 곳이 화면 · 읽어 주기 · AI 입력 · 저장 · 일치율 견주기(talk.hint_read_match) 다섯으로 는다. (3) 수업 흐름에 선생님이 자기 이름을 말할 자리가 없다. 자기소개는 명단의 인사가 맡고, 수업 중에는 AI 가 고정부로 제 이름을 안다. (4) 6.4 '틀 자리는 {NAME} 하나만'과 실시간 낱말 범위 검사가 그대로다. (5) 선생님을 늘려도 시드를 고치지 않는다.

| 정본 절 | 바뀐 것 |
|---|---|
| 6.3 회화 카드 · 회화 평가 카드 · 선생님 이야기 | 모든 글 칸(영어 · 한국어, 예상 흐름 · 오늘 쓸 말 예문 · 안전한 대사 · 끝인사 포함)에 선생님 이름을 쓰지 않는다. 예상 흐름은 'The teacher asks …' 꼴이다. 선생님 자기 이야기(2단계 'And you?' 앞 말 등)는 어느 선생님이 해도 맞는 말로 쓴다. 좋아하는 것 정도이고 종(다람쥐) · 성별 · 나이 · 가족 · 사는 곳은 쓰지 않는다. 생성 브리프(_template · 회화 브리프)에 이 규칙을 둔다 |
| 6.4 회화 시나리오 카드 · 회화 평가 카드 · 선생님 이야기 | 새 검사 '선생님 이름'. 글 칸에 'Tori' · '토리'와 명단의 영어 · 한글 이름이 있으면 그 칸을 막는다. 영어는 대소문자를 가리지 않고 낱말 경계로 보고, 한국어는 이름 뒤 조사를 허용해 본다. 명단을 늘리면 이 검사가 모든 시드를 다시 본다. '틀 자리는 {NAME} 하나만'(talk-placeholder)은 그대로라 `{TEACHER}` 는 지금처럼 막힌다 |
| 6.4 명단 자료(새 행) | 아래 '데이터'의 칸 검사와 '자산과 라이선스'의 자산 검사 |
| 6.3 수업 종류 '토리 이야기' | 문서 · 화면 이름을 '선생님 이야기'로. 내용 규격(짧은 이야기 · 한국어 뜻 · 질문 2개)은 그대로 |

종 · 성별 같은 '어느 선생님이 해도 맞는 말'은 기계로 다 잡을 수 없다. 생성 브리프와 시드 표본 검토(아이 눈 분해)에서 본다.

P8 과의 차례가 걸린다. C118 순서로는 이 변경이 P8 뒤인데, 회화 카드 본 생성(6.3 (4-나))은 P8 안에 있다. 그래서 시드 쪽 몫(명단 자료의 이름 칸 · '선생님 이름' 검사 · 생성 브리프 규칙)은 P8 회화 묶음 앞에 먼저 들인다(미결 2). 지금 보이는 걸림은 셋이다. seed/vocab.json 예문 넷('Hello, I am Tori.' · 'Goodbye, Tori!' · 'Say hello to Tori.' · 'Tori is a squirrel.')을 회화 카드 오늘 쓸 말 예문으로 옮기면 새 검사에 걸린다. 읽기 생성 브리프(seed/prompts/reading-1.md)가 등장인물 Momo · Tori 를 제안한다(장부 116행, 미결 1). 시험용 시드 나무(p13 tests/fixtures/seed/builders.ts)의 회화 카드 질문 · 예상 흐름에 'Tori' 가 있어 함께 고친다.

CI 에서 WebGL 이 없을 때의 길은 이렇다. GPU 없는 머리 없는 크롬은 M139 부터 소프트웨어 WebGL 로 저절로 넘어가지 않아 WebGL 맥락을 만들지 못하고, `--enable-unsafe-swiftshader` 깃발을 주어야 한다(Chromium 문서 'Using Chromium with SwiftShader' · Chrome Enterprise 정책 EnableUnsafeSwiftShader, 2026-10-23 확인. 우리 CI 러너에서 되는지는 구현하며 확인). 그래서 기본 프로젝트가 대신 표시 길을 늘 시험하고, 3D 프로젝트는 깃발로 돈다. 3D 프로젝트가 러너에서 WebGL 을 못 만들면 건너뛰지 않고 실패로 보고해 드러나게 한다. 3D 시험 모델은 실제 모델이 저장소에 없을 수 있으므로 시험용 작은 VRM(허용된 것)이나 제공 길의 줄인 파일을 쓴다. plan 이 정한다.

9절 '컴포넌트 단위 시험은 두지 않는다'는 그대로다. 상태 · 조사 · 목소리 · 명단은 순수 함수로 단위 시험하고, 화면은 Playwright 로 본다.

## 우려 사항 (Flagged concerns)

1. 아이 이름이 선생님 이름과 같으면 그 선생님이 빠진다. 지금 명단은 둘이라 이름이 미나(Mina)나 리오(Leo)인 아이에게는 한 명만 보인다. 빼지 않으면 {NAME} 바꾸기가 대화 기록 속 선생님 자기 말('I'm Mina')까지 바꿔 AI 가 헷갈린다. 명단이 늘면 덜하다.
2. iPad 성능을 모른다. 원본은 17~19MB · 정점 70만~170만이고, 시제품은 데스크톱 크롬에서만 확인했다. 줄인 뒤에도 인식 · 읽어 주기와 함께 15분을 그릴 때 발열 · 프레임 · 인식 지연이 미지수다. 안 되면 talk.teacher_render 를 portrait 로 둬 초상으로 수업한다. 모델을 다 받은 뒤 푸는 일은 주 실행 줄에서 돌아 아이 차례의 시간 재기(확인 2초 · 듣기 끝 대기)를 몇백 ms 늦출 수 있다. 듣는 동안에는 풀기를 미룰지 구현하며 확인한다.
3. 리오 목소리. 기기에 남성 영어 목소리가 없으면 리오는 기본 목소리에 높이만 낮춰 읽는다. 높이로 성별 느낌을 바꾸기는 어렵다. iPad 목소리 목록을 실측해 순서를 정한다.
4. C16 을 고친다. 고르기 전 문구 '선생님이 잠깐 쉬어요'는 C16 이 쓰지 않는다고 적은 바로 그 문구다. 까닭이 없어졌고 C117 의 뜻에 맞지만 13절 고침 한 줄이 먼저다. 고른 뒤에는 읽기 · 쓰기 화면에도 회화 선생님 이름('미나가 잠깐 쉬어요')이 나온다. 모든 영역을 한 인물로 묶은 C16 의 뜻을 잇는 것이다.
5. P8 과의 차례. 시드 쪽 몫이 P8 회화 묶음보다 늦으면 이미 만든 회화 카드가 새 검사에 걸려 다시 만들어야 한다(미결 2).
6. vocab 예문 넷과 읽기 등장인물 Tori. 회화 쪽은 새 검사가 막지만, 읽기 · 쓰기 · 말하기 글에 Tori 를 남길지는 이 변경이 정하지 않는다(미결 1).
7. 모델 제공 길. 원본을 저장소에 안 넣는 것은 지키지만, 줄인 파일을 넣으면 파일당 수 MB × 명단 수만큼 저장소가 커진다. 빌드 때 받으면 배포가 바깥 주소에 기대고, 비공개 저장소면 토큰이 는다(미결 3).
8. 미나 파일 안 licenseName 은 'Other'이고 배포 페이지 설명은 CC0 다. 기준은 파일 안 VRoid Hub 조건(상업 · 고쳐 쓰기 · 재배포 허용 · 크레딧 불필요)이고 시제품 LICENSES.md 가 이 차이를 그대로 적었다. 줄인 파일에서 메타를 잃으면 근거가 사라지므로 자산 검사로 막는다.
9. C115 의 '3D 맥락을 잃으면 다시 불러오기 안내'를 가져오지 않는다. 수업 중 아이 화면에 두 번째 행동이 생기지 않게 조용히 초상으로 바꾸고 다음 세션에 다시 3D 를 시도한다. 요청자가 안내를 원하면 바꿀 수 있다.
10. 3D 는 회화 세션에만 있다. 회화 단계 평가 · 선생님 이야기는 초상이라 '화상영어 느낌'이 수업에만 있다(미결 7).
11. CI 에서 3D 길이 돌지 않을 수 있다. 머리 없는 크롬은 깃발이 있어야 소프트웨어 WebGL 을 쓴다. 러너에서 안 되면 3D 바꿈 · 요청 한 번 · 맥락 잃음은 로컬 · 프리뷰 점검으로만 남는다.
12. 코드 식별자(tori_en · tori_ko · tori_story · tori_nickname · 화자 tori · ToriFigure · TORI_TEXT)가 문서 · 화면 이름과 어긋난다. 코드 식별자는 영어를 허용하므로 DB · AI 스키마 이름은 그대로 두기를 권한다. 스키마 필드 이름을 바꾸면 문법 컴파일 · 녹화 표본 · 열 이름이 함께 바뀐다(미결 6).
13. 칭찬을 켜는 때(따라 말하기 '잘 말했어요' · 목표 턴 · 미션)가 아이에게 적어 보일 수 있다. 대화 토막은 R2 때문에 칭찬을 묶지 않는다. 첫 판 프리뷰에서 본다.
14. 끝 알림이 오지 않는 WebKit 읽어 주기(버그 321436 류)에서는 입이 계속 움직인다. 지금 읽어 주기 줄이 멈추는 것과 같은 때이고, 말하기 단추가 둘 다 끝낸다(C53).

C117 로 토리는 회화 선생님에서 빠졌다. 그런데 vocab.json 예문 넷이 Tori 를 쓰고('Hello, I am Tori.' 등), P8 읽기 브리프는 등장인물을 Momo · Tori 둘로 제안했다(장부 116행, 읽기 표본이 지금 만들어지는 중). 회화 쪽은 새 검사가 막으므로 선생님과 섞이지 않는다. 선택지는 (가) Tori 를 모모의 다람쥐 친구로 남긴다, (나) Tori 를 빼고 다른 이름 하나를 정한다(예문 넷 · 브리프 고침), (다) Momo 하나만 쓴다. 권하는 안은 (가)다. 1단계 글이 두 인물의 짧은 대화를 쓸 수 있고, 지금 표본 · 예문을 고치지 않아도 되며, 회화와는 검사로 갈린다.
2. 컨트롤러가 정할 것. 시드 쪽 몫(명단 자료의 이름 칸 · '선생님 이름' 검사 · 생성 브리프 규칙 · 시험용 시드 나무)을 C118 순서보다 앞, P8 회화 묶음 앞에 들일지. 권하는 안은 앞에 들이기다. 작고 3D 와 떨어져 있으며, 늦으면 만든 카드를 다시 만든다.
3. plan 이 정할 것. 줄인 모델 제공 길(저장소에 넣기 · 빌드 때 받기 · 비공개 저장소)과 줄이기 도구 · 값. 권하는 안은 줄인 파일이 수 MB 이면 저장소에 넣기다(바깥 기댐 없음, 해시 검사가 쉬움).
4. 실측으로 정할 것. talk.teacher_model_max_mb · talk.teacher_load_timeout_seconds 값, 그리기 빈도 · 화소 비율 상수, 리오 목소리 순서(AC-N1).
5. 첫 판 프리뷰에서 볼 것. 칭찬을 켜는 때가 모자란지, 선생님 창 크기, 고르는 화면의 '인사 듣기'가 고르기에 도움이 되는지.
6. plan 이 정할 것. 코드 식별자 이름. 권하는 안은 DB · AI 스키마 이름(tori_en · tori_ko · tori_story · tori_nickname · 화자 tori)은 그대로 두고, 화면 조각 이름(ToriFigure · TORI_TEXT)과 데이터 속성만 teacher 로 바꾸기다.
7. 회화 단계 평가 · 선생님 이야기에도 3D 를 둘지. 사용 시험 뒤 본다(이번 범위 밖).
