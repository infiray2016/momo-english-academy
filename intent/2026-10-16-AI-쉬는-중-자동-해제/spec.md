## 요약 (Summary)

정본에는 AI 를 못 쓰는 때를 'AI 쉬는 중' 하나로 다루는 원칙(S9), 진행을 끊지 않고 매우 높은 안전 상한만 두는 원칙(2026-10-15 10:17), 콘솔 월 지출 한도가 마지막 방어선이라는 원칙(R4)이 있었다. 이 변경으로 부모 버튼 'AI 다시 켜기'가 없어지고 앱 진입 · 부모 화면 요청 때의 1토큰 확인 호출로 저절로 풀리며, 하루 안전 상한은 다음 학습일에만 풀리게 되어 1,000회 · 15달러로 올랐다(T1 · C1 · C15 · C29). 이 내용은 검토 4 · 5회차에 정본 열한 장에 모두 들어갔고, 컨트롤러 검토(05:3x)에서 부모 화면 칸 값 · 문구 속 간격 · 콘솔 한도 오류 표본 · 확인 호출 입력 글 · 풀린 뒤 알림을 C46 으로 정해 정본에 넣었고, 새 AC 둘은 승인 뒤 15절에 넣는다(우려 9 · 10 · 11 · 13 · 14 · 17).

## 요구사항 (Requirements)

| 번호 | 이 변경으로 바뀐 문장 | 근거 |
|---|---|---|
| FR-18 | 'AI 쉬는 중'을 푸는 부모 버튼이 없다. 하루 안전 상한은 다음 학습일에만 풀리고 확인 호출을 보내지 않는다. 콘솔 한도 · 연결 장애 · 계정 확인 필요는 확인 호출이 한 번 성공하면 저절로 풀린다 | T1 · C1 |
| FR-18 | 확인 호출은 앱 진입(홈 화면 요청)과 부모 화면 요청 때 다음 확인 시각이 지났으면 응답 뒤에 하나 보낸다. 간격은 연결 장애 5 · 15 · 30분, 콘솔 한도 · 계정 확인 필요 60분이다. 최대 출력은 1토큰이고 HTTP 200 이면 성공이다 | T1 · C1 · C29 |
| FR-18 | 확인 호출이 실패하면 실패 종류로 까닭을 다시 정한다. 풀리면 이어진 실패 수와 확인 차례를 0 으로 되돌린다. 밀린 첨삭과 끝맺음 턴은 풀린 뒤 첫 앱 진입 때 부른다 | S9 · C17 |
| FR-18 | 부모 화면 'AI 쉬는 중' 행과 아이 화면에 버튼이 없다. 부모 화면은 까닭 · 풀리는 시각 · 다음 확인 시각 · 까닭별 안내 · 오늘 호출 내역만 보인다. 아이 화면 문구는 모든 영역 '토리가 잠깐 쉬어요'다. AI 가 필요한 카드를 누르면 ai_status 를 다시 읽는다 | T1 · C16 · C29 |
| FR-18 | 하루 안전 상한은 풀리는 시각과 다음 확인 시각이 둘 다 다음 학습일 시작이다. 그 시각이 지나면 ai_status 를 읽는 첫 요청이 확인 호출 없이 푼다. 연결 장애 · 계정 확인 필요는 풀리는 시각을 비운다. 콘솔 한도 문구의 간격은 ai.probe_interval_minutes 에서 채운다 | C46 |
| FR-12 | 1차 부모 화면에 'AI 쉬는 중'의 까닭 · 풀리는 시각 · 다음 확인 시각 · 까닭별 안내 · 오늘 호출 내역을 둔다 | T1 · C29 |
| FR-8 | 문장은 그대로다. 하루 안전 상한 값만 1,000회 · 15달러로 올랐다(6.1 · 12절). 확인 호출은 하루 호출 수 · 비용 알림 · 안전 상한에 넣지 않고 모델 설정 키를 쓰지 않는다 | C15 · C1 |

NFR-2 는 바뀐 문장이 없다. 콘솔 한도가 마지막 방어선이라는 문장(R4)과 콘솔 한도 80% 알림(C28)은 그대로다. 이 변경으로 없어진 것은 'AI 다시 켜기' 버튼과 '하루 상한을 같은 만큼 한 번 더 연다'다(13절 없어진 것 표 · S9 의 세부 행).

| 범위 밖 | 대신 하는 것 |
|---|---|
| 앱 안 월 상한 | 콘솔 월 지출 한도가 마지막 방어선이다. 앱은 월 비용 알림과 콘솔 한도 근접 알림만 한다(R4 · C28) |
| 앱이 콘솔 한도를 바꾸기 | 부모가 Anthropic 콘솔 Billing 에서 올린다. 콘솔 한도를 바꾸면 ai.console_limit_usd 도 같은 값으로 바꾼다(10절) |
| 아이가 푸는 길 | 아이 화면에 버튼이 없다. AI 없이 되는 공부로 안내한다(8절) |
| 프로필마다 따로 쉬는 상태 | 1차는 집 전체 한 행이다. 3차 전에 정한다(11절 3차) |
| 1-가의 쉬는 상태와 확인 호출 | 1-가는 안전 상한에 닿으면 그 학습일의 실시간 호출만 막고 안내한다. 상태와 확인 호출은 1-나다(11절, B5-20) |

## 설계 (Design)

### 화면

| 정본 절 | 바뀐 것 |
|---|---|
| 4절 홈 · 수업 목록 'AI 쉬는 중' | 버튼이 없다. AI 가 필요한 활동만 있는 카드(회화, 쓰기 4단계 이상, 말하기 9단계 이상)와 AI 가 필요한 수업 포스트잇에 '토리가 잠깐 쉬어요'를 작게 붙인다. 누르면 '토리가 잠깐 쉬어요. 다른 공부를 해 볼까요'와 '홈'을 보인다. 홈 카드는 그 영역에 복습할 카드가 있으면 '복습하기'를 함께 둔다. 누를 때 ai_status 를 다시 읽어 풀렸으면 바로 연다(C16 · C29) |
| 4절 부모 화면 'AI 쉬는 중' | 버튼이 없다. 까닭, 풀리는 시각(한국 시간), 다음 확인 시각, 오늘 호출 수와 비용(목적별 · 세션별)을 보인다. 까닭별 문구 넷(콘솔 한도 · 계정 확인 필요 · 하루 안전 상한 · 연결 장애)은 4절 그대로다. 이 화면을 열 때도 다음 확인 시각이 지났으면 확인 호출을 하나 보낸다(T1 · C29) |
| 4절 부모 화면 칸 값 | 하루 안전 상한은 풀리는 시각과 다음 확인 시각을 같은 다음 학습일 시작으로 둔다. 연결 장애 · 계정 확인 필요는 풀리는 시각 칸을 비운다. 콘솔 한도 문구의 '한 시간'은 ai.probe_interval_minutes 값을 읽는 말로 바꿔 넣는다(C46) |
| 4절 알림 목록 | 'AI 쉬는 중'은 까닭에 '계정 확인 필요'를 포함한다(C1). '콘솔 한도 근접'(C28)과 '호출 설정 확인 필요'(C17)가 함께 있다 |
| 11절 목업 | B_Parent 에 다음 확인 시각과 까닭별 문구를, B_Home4 에 '토리가 잠깐 쉬어요'를 더한다. 1차 부모 화면과 'AI 쉬는 중' 안내는 새로 그린다. 1-가 시드 확정 때 한다 |

### AI 호출 · 규격

| 정본 절 | 바뀐 것 |
|---|---|
| 6.1 표 확인 호출 행 | 모델은 ai_status 의 확인 모델(쉬게 한 마지막 실패 호출의 모델)이고, 콘솔 한도 · 계정 확인 필요면 claude-haiku-5-5 다. 그 모델의 가장 가벼운 조합으로 보낸다(Haiku 5.5 low · disabled, Sonnet 5.5 low · between_tools, Opus 5.5 low · adaptive). 타임아웃은 ai.timeout_seconds.realtime, 최대 출력은 ai.max_tokens.probe(1)다. ai.model · ai.effort · ai.thinking 키는 쓰지 않는다(C1, B5-11) |
| 6.1 정규화 · 기록 · 재시도 | 확인 호출은 정규화를 쓰지 않고, HTTP 200 이면 stop_reason 과 관계없이 성공이다. ai_calls 에 목적 '확인'으로 profile_id 없이 남긴다. SDK 기본 재시도는 끈다(max_retries 0). 콘솔 한도 오류는 다시 보내지 않고 바로 쉬는 상태로 간다(C1) |
| 6.1 알림 문단 | 하루 안전 상한은 프로필의 그날 실시간 호출 ai.safety_daily_calls(1,000회)와 가정의 그날 비용 ai.safety_daily_cost_usd(15달러)다. '많이' 하루(높은 단계 약 180회 · 약 3.5달러)의 호출 약 5.6배 · 비용 약 4.3배다. 확인 호출은 이 합계와 알림 기준에 넣지 않는다(C15 · C1) |
| 6.2 | 확인 호출 행을 더했다. 입력은 아이 정보가 없는 고정 한 단어 'ok', 출력 규격 없음, HTTP 200 이면 성공(C46) |
| 6.6 | 두 가정에 확인 호출 비용을 넣지 않았다. 사고가 이어지면 하루 15달러씩 쌓일 수 있고 달 단위는 콘솔 한도가 막는다. 월 알림 4배(48달러)와 콘솔 한도 80% 알림(56달러)이 한도 앞 알림이다(C15 · C28 · C42) |

### 처리 규칙 · 판정

| 정본 절 | 바뀐 것 |
|---|---|
| 8절 들어가는 조건 | 계정 오류(401 · 402 · 403) 한 번을 넷째 조건으로 더했다(C1). 다시 보내도 같은 오류는 넣지 않고(C17), 이어진 실패 수는 턴마다 센다(C18). 하루 안전 상한 · 콘솔 지출 한도 오류(400, 429 enforced_spend_limit_reached) · 연결 · 서버 오류 ai.down_after_failures 번은 그대로다 |
| 8절 풀리는 조건 | 하루 안전 상한은 다음 학습일에만 풀린다. 나머지는 확인 호출이 한 번 성공하면 풀린다. 콘솔 오류 메시지의 풀리는 시각이 지나면 첫 앱 진입에서 바로 보낸다. 실패하면 콘솔 한도 오류는 '콘솔 한도', 401 · 402 · 403 은 '계정 확인 필요'로 까닭을 바꾸고, 그 밖의 오류는 까닭을 두고 확인 차례를 올린다(T1 · C1 · C17) |
| 8절 확인 호출 | 앱 진입과 부모 화면 요청 때 응답 뒤(after())에 보낸다. ai_status 의 다음 확인 시각을 먼저 미루는 데 성공한 요청 하나만 보낸다(T1 · C1 · C29) |
| 8절 풀기 판정 | 하루 안전 상한은 다음 확인 시각이 지난 뒤 ai_status 를 읽는 첫 요청(홈 · 부모 화면 · 카드 누름)이 확인 호출 없이 시각만 보고 푼다(C46) |
| 8절 동안 · 첨삭 · 목표 턴 뒤 회화 | 변경 없음. 풀린 뒤 첫 앱 진입에서 밀린 첨삭과 끝맺음 턴을 응답 뒤에 부른다 |
| 3.1 학습일 · 11절 차수 | 변경 없음. 하루 안전 상한과 '다음 학습일'은 app.timezone · app.day_start_hour 로 센다. 안전 상한 판정 · ai_calls · parent_alerts 는 1-가, 상태 · 확인 호출 · 부모 화면은 1-나다 |
