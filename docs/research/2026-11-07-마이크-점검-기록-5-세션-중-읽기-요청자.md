# 마이크 점검 기록 5 — 세션 중 읽기(S · S2 ×4), 요청자 목소리(2026-11-07 02:52~02:55 KST)

출처: 점검 쪽 서버 로그 끝점 기록(Vercel '[mic-probe]'). 고치지 않는다. 요청자는 S 한 번 뒤 S2 를 네 번 했고(각각 '멈추기'), 모든 세션은 누름 안에서 무음 읽기(unlock)를 먼저 했다. 들은 글은 길이만.

규칙성(컨트롤러 첫 읽기):
1. as 띠 규칙 재확인: 299 · 305 · 1024 는 됨, 197 · 202 는 못 들음(문턱 200~250 사이, 202 는 못 들음).
2. **살아 있는 세션에서는 읽기(speechSynthesis)가 멈춘다**: 무음 읽기의 speak-start 가 audiostart 와 같은 때 오고 speak-end 가 오지 않아 speaking=true 로 남고, 그 뒤 '세션 중 읽기' 두 번은 줄만 서고 시작되지 않았다(3 · 5). 반대로 **죽은 세션에서는 읽기가 정상 재생**됐다(2 · 4). 즉 캡처가 실제로 살아 있으면 TTS 가 안 나온다(321436 댓글 2 의 '읽는 동안 인식 없음 · 큐 멈춤'과 같은 축).
3. **번갈아 나타남**: 살아 있는 세션(1) 뒤 → 죽음(2), 죽은 세션(2) 뒤 → 살아남(3), 살아 있는 3 뒤 → 죽음(4), 죽은 4 뒤 → 살아남(5). 321436 댓글 3 의 '못 듣기 · 되기 번갈아'와 같다. 죽은 세션이 10~13초 돈 뒤 사람 stop 으로 끝난 경우다(기록 1 · 2 의 짧은 죽은 세션 뒤에는 다시 죽었음 — 길이 · 종료 방식이 변수일 수 있음).
4. 읽기와 인식을 함께 쓰려면 '세션 하나를 계속 켜 두기'(W2)는 그대로는 안 된다. 대신 '선생님 말 동안 버림(죽은) 세션을 돌리고 아이 차례에 진짜 세션을 새로 켜기' 꼴을 시험할 가치가 있다(죽은 세션 중에는 TTS 가 정상, 죽은 세션 뒤 다음 세션이 살아남).
