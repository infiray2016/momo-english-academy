## 수업 생성과 관리

만드는 사람 · 고치는 사람 · 운영하는 사람(요청자 한 사람)의 눈으로 6.3 · 6.4 · 5절 · 11절을 봤다. 4회차에서 고친 차례(표본 → (4-가) 읽기 · 쓰기 · 말하기 → 1-나 회화 턴 → (4-나) 회화 카드)와 seed/checks · seed/reviews · seed/manifest · seed/reports 의 역할, 시드 보기 화면, 신고 판단 파일 → main 작업 → 다시 계산의 한 바퀴는 서로 맞물린다. CI 는 API 를 부르지 않고, 정정 칸의 풀이 검사와 사람 확인 해시도 이어진다. 볼트 훅 문장은 훅 파일과 맞다(seed/ 는 설계 접두어 밖이라 45분마다 기록을 요구한다). 끊긴 곳은 말하기 그림, 회화 카드의 턴 수와 자리 수 검사, '더 이야기할 거리'의 노리는 단어, 1단계 카드의 질문 되풀이, 평가 카드의 겹침 기준, 생성 차례 앞의 준비물, 사람 작업 시간, 신고 한 바퀴의 끝 상태, '없어진 것' 표다. 첫 운영 배포에 필요한 시드는 수업 약 3,600(그 가운데 회화 카드 900, 1~3단계 카드 390장에 '더 이야기할 거리'가 붙는다), 단계 평가 문항 1,080, 회화 평가 카드 36장(평가 턴 360), 배치 144, 토리 이야기 40 이다.

## 근거로 확인한 외부 사실

2026-10-16 에 원문을 내려받아 확인했다. 이 세션의 앞 검토자가 2026-10-15 에 내려받은 사본을 연 것은 따로 적었다.

- Anthropic, Errors(https://platform.claude.com/docs/en/api/errors). 404 not_found_error 는 요청한 자원이 없을 때, 413 request_too_large 는 요청 바이트가 한도를 넘을 때 온다. 400 invalid_request_error 는 표에 없는 다른 4XX 에도 쓰인다. 원문 확인(B5-01).
- Anthropic, Model deprecations(https://platform.claude.com/docs/en/about-claude/model-deprecations). 은퇴한 모델의 요청은 실패한다. 공개 모델의 은퇴는 쓰고 있는 고객에게 최소 60일 전에 알린다. 원문 확인(B5-01).
- Anthropic, Prompt caching(https://platform.claude.com/docs/en/build-with-claude/prompt-caching). 최소 캐시 길이는 Opus 5.5 · Sonnet 5.5 · Haiku 5.5 가 512 토큰이다. 요청 맨 위의 cache_control 하나로 거는 자동 캐시는 대화가 자라면 캐시 자리를 마지막 블록으로 옮긴다. 기본 수명은 5분이고 쓸 때마다 갱신된다. Sonnet 5.5 는 캐시 읽기 100만 토큰당 0.10달러(기본 입력의 0.05배) · 5분 캐시 쓰기 2.50달러, Haiku 5.5 는 쓰기 0.125 · 읽기 0.01달러다. 캐시를 찾는 범위는 캐시 자리에서 뒤로 20블록이다. 원문 확인(B5-14, 6.1 캐시 판단).
- Anthropic, Structured outputs(앞 검토자 사본). output_config.format 을 바꾸면 그 대화의 프롬프트 캐시가 무효가 되고, 컴파일한 문법은 24시간 캐시된다. 사본 확인. 6.1 의 '회화 턴과 끝맺음 턴은 같은 스키마'가 이것과 맞는다.
- Anthropic, Building with thinking(앞 검토자 사본). 생각 토큰은 출력으로 과금되고 max_tokens 에 함께 세어지며, max_tokens 는 엄격한 한도다. 사본 확인(B5-04).
- MDN, SpeechRecognitionAlternative(mdn/content main 판). 인식 결과는 transcript 와 confidence(0~1, 인식이 맞을 확신)뿐이다. 원문 확인(B5-25).
- MDN, SpeechRecognitionErrorEvent.error(mdn/content main 판). no-speech 는 '말소리가 감지되지 않음', audio-capture 는 '소리 받기 실패'다. 원문 확인. no-speech 가 아이의 침묵과 마이크 고장을 가리지 못한다는 것은 정의에서 끌어낸 검토자 추론이다(B5-05).
- Supabase, Database size(supabase/supabase master 의 apps/docs/content/guides/platform/database-size.mdx). 무료 프로젝트는 DB 크기가 500MB 를 넘으면 읽기 전용이 된다. 이와 따로 공정 사용 제한은 조직의 모든 프로젝트 DB 크기를 더한 청구 기간 일 평균으로 보고, 걸리면 402 응답 등을 건다. 원문 확인. 무료 조직의 할당이 합계 500MB 인지 프로젝트 수만큼인지는 문서에서 가리지 못했다(부분 확인, B5-09 · B5-27).
- Supabase, Billing FAQ(같은 저장소의 billing-faq.mdx). 무료 프로젝트는 두 개까지 쓸 수 있고(정지한 것은 세지 않음) 무료 조직을 따로 만들 수 있다. 공정 사용 제한은 대개 제한받은 조직의 모든 프로젝트에 걸리고, 402 응답 · 읽기 전용 · 일시 정지가 될 수 있다. 원문 확인(B5-09).
- 확인하지 못한 것. 모델의 출력 속도(끝맺음 턴이 10초를 넘는지), Opus 5.5 에 low · adaptive · 최대 출력 1토큰을 보낼 때 400 없이 받아지는지(4회차와 같음)는 문서로 확인하지 못했다. 캐시를 넣은 비용, 턴마다 느는 입력, 회화 카드의 출력 크기, 사람 작업 시간, 영역 사이 단원 단어 겹침의 비율, 말하기 그림 수, 1단계 카드 질문 만들기의 어려움은 검토자 계산 · 추정이다.
