## 1부 — 기술 · 데이터 · AI · 운영
- 'AI 쉬는 중' 상태(S9, 8절 표 · 5절 ai_status · 6.1 확인 호출 · 12절 ai.down_*). 들어가는 조건 셋과 풀리는 조건 셋이 빠짐없이 맞물리는지, 확인 호출(Haiku 1토큰)이 콘솔 한도 상태에서 무엇을 돌려주는지, 'AI 다시 켜기'가 하루 안전 상한을 한 번 더 여는 설계(13절 1093줄)가 사고를 막는 안전 상한의 뜻과 부딪치지 않는지, 상태가 집 전체 하나일 때 두 기기 · 두 프로필에서 생기는 일, 쉬는 중에 들어오던 요청(스트리밍 도중 · 첨삭 대기)의 처리.
- Haiku 5.5 설정(B3-01 정정 뒤). disabled 가 6.1 · 6.6 · 9절 · 12절 · 13절 · FR-8 · AC-8f 에 일관되게 적혔는지, 모델 · effort · thinking 조합 표와 저장 검사, Haiku 거절 → Sonnet 한 번 재시도의 비용 · 캐시 · 스키마 영향, 대체 모델 재시도 1시간 고정과 비용 기록.
- 회화 턴 스키마와 저장(S1 · S5). '스스로 쓴 단원 단어' 필드의 Zod 검증 · 원형 확인 · 저장 열(talk_turns 힌트 종류 · 노린 단어 · 돌려준 단어 · 센 단어), 1~3단계 '반응 + 앱이 붙이는 카드 질문' 구조에서 읽어 주기 · 문장 검사 · 캐시가 어떻게 되는지, '더 이야기할 거리'를 다 쓴 뒤 AI 가 만든 질문 · 힌트의 검증과 되돌림.
- 시드 판 · 정정 · 적재(B3-10 · B3-12 반영 뒤). 칸마다 판 번호, 같은 결함의 여러 개정 정정, 평가 '시작 개정', 마이그레이션 → 검증 → 적재 순서와 Deployment Checks, 정정 커밋이 만드는 배포의 승격 타이밍.
- 첫 운영 배포 범위(S4 · S8). 1-가 · 1-나 경계가 테이블 29 · FR-18 · AC · 9절 테스트와 맞는지, 1-가 프리뷰 배포(개발용 DB)에서 요청자가 써 볼 때 빠진 것(부모 확인 화면은 1-나 등), 단계 평가 · 복습 · 숙달이 1-가에 들어오면서 순수 함수 목록 · 테스트가 다 있는지.
- 설정 키 구간화와 설정 판(unit_progress 복사본 · 새 회차) · 시드를 다시 만들어야 하는 키 목록이 12절 · 5절 · 6.3 · 3.2 에서 일관된지. 12절 키 바뀜 문단이 실제 표와 맞는지.
- 음성 규칙(S7 뒤). 마이크를 쓸 수 없음의 판정(API 없음 · 권한 거부 · 장치 없음)과 일시적 실패의 경계, 듣기를 끝내는 때(한 문장 · 여러 문장), '다 말했어요', Chrome Android 다시 시작, 감시 타이머, iPad 실기 확인 항목이 7절 · 8절 · 9절 · AC 에 빠짐없이 있는지.
- 접근 제어 · RLS 가 새 서버 액션('AI 다시 켜기' · 신고 · 단계 바꾸기 · 대화 지우기)에도 그대로인지. 3회차 '대상 없음' 처리와 잠정 23행 가운데 기술 쪽(1089 · 1090 · 1092 · 1093 · 1094 · 1095 · 1096 · 1097 · 1099 · 1100 · 1102 · 1103 · 1108)이 타당한지.
