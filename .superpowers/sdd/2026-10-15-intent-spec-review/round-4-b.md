# 4회차 B — 기술 · 데이터 · AI · 운영 관점

분석가 B 가 2026-10-15 에 읽기 전용으로 검토했다. 문서 · 코드 · 볼트는 고치지 않았고 커밋하지 않았다. 하위 에이전트를 띄우지 않았다.

본 자료는 `.claude/CLAUDE.md`(17:4x 판), intent(34줄), spec(1247줄, 1~15절 전부), `round-3-applied.md`, `task-r3-apply.md`(S1~S10)와 `task-r2-apply.md`(R1~R15), 3회차 보고 `round-3-a.md`(대상 없음 세 건) · `round-3-b.md`, 브리프 `task-r4-review-common.md` · `task-r4-review-b.md` 다. `.claude/agents/curriculum-designer.md`, 전역 훅 `~/.claude/hooks/vault_check.py`, 목업 `docs/media/mockups/B_Parent.dc.html` 의 글도 열었다. 새로 쓴 외부 사실은 원문을 내려받아 확인했고 문서 끝에 출처와 확인 정도를 적었다. 3회차 B 가 확인한 사실(모델 단가 · thinking 값 · 대체 모델 재시도 · Supabase 키 · Deployment Checks 의 승격 보류)은 다시 적지 않았다.

숫자 검산은 모두 맞았다. 정규 수업 2,835(읽기 · 말하기 · 회화 각 765, 쓰기 540), 보강 966, 수업 소계 3,821, 변형까지 7,642, 회화 카드 2,010, 단계 평가 문항 2,160(1~6단계 1,080), 회화 평가 카드 147(1~6단계 87), 배치 144, 토리 이야기 80 이다. 첫 운영 배포 수업은 3,592(읽기 · 말하기 · 회화 각 900, 쓰기 840, 알파벳 52)로 '약 3,600'과 맞는다. 6.6 의 1회 비용 넷과 사용량 표 여섯 칸(0.5 · 2.4 · 2.6 · 16 · 4.5 · 26달러), 3차의 1.5~13.5 · 7~78달러도 같은 단가 · 토큰 가정으로 다시 내면 맞는다. 3.4 의 하루 복습 최대 45장(약 4.5분), 5절 테이블 29개, 3.2 분량 표(단계 50~75회, 쓰기 세션 800회)도 맞다. 12절 표와 본문의 설정 키 이름도 서로 맞다(본문에 쓴 키 가운데 표에 없는 것은 없앤 level.task_item_pass 하나다).

가장 큰 문제는 셋이다. 첫째, 1~3단계 회화는 힌트가 늘 보여 한국어 뜻만 보이는 다시 묻는 턴에서만 단원 단어가 '말했다'가 된다. 그런데 카드 규칙으로는 그 턴이 다지기 · 보강 수업에만 들어가, 아이가 모두 맞게 말해도 정규 · 보강 수업만으로는 단원 통과에 필요한 횟수에 닿지 못한다(B4-M-01, 결정 B4-D2). 둘째, 'AI 쉬는 중'은 들어가는 조건에 키 만료 · 결제 오류가 없고, 푸는 확인 호출이 Haiku 로만 가서 Opus · Sonnet 장애가 풀렸는지 알 수 없으며, 콘솔 한도에서 부모 화면 문구와 풀리는 규칙이 어긋난다(B4-01 · B4-03 · B4-04). 셋째, 시드 판 번호를 칸마다 세면 '시작 개정 이하' 규칙이 깨지고, 1차에 설정값을 시드로 바꾸는 적재 규칙이 없다(B4-09 · B4-10). 이대로 만들면 아이 · 부모가 앱을 못 쓰거나 비용 사고가 나는 곳은 찾지 못해 Critical 은 없다.

만드는 사람 · 고치는 사람 · 운영하는 사람(요청자 한 사람)의 눈으로 6.3 · 6.4 · 5절 · 11절을 봤다. 첫 운영 배포에 필요한 시드는 수업 3,592(그 가운데 1~3단계 회화 카드 390장에 '더 이야기할 거리' 묶음이 붙는다), 단계 평가 문항 1,080, 회화 평가 카드 87(평가 턴 375), 배치 144, 토리 이야기 40 이다. 사람이 볼 일은 표본 48개(1~6단계 24묶음 × 2, 오류가 나오면 묶음마다 5개), 풀이 검사의 사람 확인, 분포 경고마다의 결정이다. 1~6단계에서 정답이 있는 문항은 약 9천~1만 개라, 2~5% 가 걸리면 사람 확인이 200~500건이다(검토자 추정, 3회차 B3-M-02 의 추정과 같은 크기). 검증 → 풀이 검사 → 표본 검토 → 분포 경고 결정 → 적재의 차례와 seed/checks · seed/reviews · seed/manifest 의 역할은 6.3 · 6.4 에 이어져 있고, CI 는 API 를 부르지 않는다(6.4 707줄, 9절 824줄, AC-7f). 끊긴 곳은 1~3단계 회화 카드의 다시 묻는 턴, 평가 문항과 수업의 겹침, 회화 카드를 만드는 때, 사람이 볼 도구, 표본을 만드는 길, 프롬프트 판의 범위, 신고를 처리하는 자리다.

## 근거로 확인한 외부 사실

모두 2026-10-15 에 원문을 내려받아 확인했다. 확인하지 못한 것은 끝에 따로 적었다.

- Anthropic, Errors(https://platform.claude.com/docs/en/api/errors). 401 authentication_error 는 키가 잘못되었거나 폐기 · 만료된 때, 402 billing_error 는 결제 · 지불 정보에 문제가 있을 때, 403 permission_error 는 키에 권한이 없을 때 온다. 직접 둔 조직 · 워크스페이스 지출 한도에 닿으면 400 이다. 429 rate_limit_error 는 요청 수 한도, 등급의 월 지출 상한, Claude Code 워크스페이스 한도에서 오고, 등급 상한 429 는 retry-after 가 없다. 529 overloaded_error 는 모든 사용자의 요청이 몰릴 때 오고, 드물게 갑작스러운 사용 증가에는 429 가 온다. 공식 SDK 는 연결 오류 · 요청 수 한도 · 5xx 를 기본 두 번 다시 보내고 max_retries 로 바꾸거나 끌 수 있다. 스트리밍은 200 뒤에도 오류 이벤트가 올 수 있다. 원문 확인(B4-03).
