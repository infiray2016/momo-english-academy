## 1부 — 기술 · 데이터 · AI · 운영
- 회화 턴의 새 호출 구조. 1~3단계 Haiku 5.5 · 4단계부터 Sonnet 5.5, effort low · thinking between_tools(편집자 잠정), 스키마(tori_en · tori_ko · 설명 · 되풀이 문장 · 새 단어, 4단계부터 다음 턴 힌트), 문장 단위 검사, {NAME} 가림, 스트리밍 중 실패 · fallback, 끝맺음 없이 떠난 대화의 다음 진입 처리. Haiku 5.5 가 structured outputs · between_tools · 서버 측 fallback 을 받는지는 Anthropic 문서 원문으로 확인해 적는다(편집자는 확인하지 않았다고 썼다).
- 시드 판 · 적재 · 정정. 판 '개정.정정' 열쇠, 정정 판이 진행 중 단원 · 다시 하기 · 남은 평가 문항에 바로 닿는 규칙, 옛 개정에 정정을 만드는 문제(편집자 남은 우려), 적재 스크립트의 멱등성과 Vercel Deployment Checks 연결, seed_reports 와 점수 재계산, 1차 1~6단계 완전성 검사와 seed.complete_through_level.
- 단계 구간별 설정 키(`unit.*.<구간>` · `ai.model.talk_turn.<구간>` 등)가 12절 · 5절 settings · 순수 함수 · 시드 검증기에서 일관되게 쓰이는지, 구간 경계에서 unit_progress 가 어떻게 읽히는지.
- 비용 모델 6.6 재계산(Haiku 단가, 중간 단계 행, 시간 총량 약 335시간, 시드 7,642개)과 알림 · 안전 상한 기본값, 콘솔 월 한도 70달러의 오류 처리. 1차 부모 화면의 비용 합계가 ai_calls 에서 어떻게 나오는지.
- 1차 범위 확대(부모 화면 · parent_alerts · seed_reports · 정정 · 배치 평가 음성 없음 행 · 알림)로 테이블 수 · FR · AC · 9절 테스트가 맞는지, 11절 1차 행이 plan 에서 나눌 수 있는 크기인지(편집자가 두 묶음으로 나눌지 물었다).
- 음성: 말하기 버튼(한 번 눌러 시작, 1.5초 조용하면 끝), 인식 글 2초 확인, 감시 타이머, iPad 실기 확인 항목, 음성 없는 기기의 힌트 누르기 · 자판 대체가 7절 · 8절 · AC 에 빠짐없이 있는지.
- 접근 제어 · RLS · 서버 전용 키가 새 서버 액션(단계 바꾸기 · 대화 지우기 · 신고)에도 그대로인지. Next.js 16 · Drizzle · Anthropic SDK 사실 확인이 필요한 문장.
- 2회차 보고의 '일부 반영' · '대상 없음' 처리(B2-12, B2-M-02 · M-11)가 요청자 결정에 맞게 됐는지.

2회차와 같은 방식이다. 만드는 사람 · 고치는 사람 · 운영하는 사람(요청자 한 사람)의 눈으로 6.3 · 6.4 · 5절 · 11절을 본다.
- 만들기: Claude Code 세션(학습 설계자 에이전트)만으로 1차 범위(배치 한 벌 + 1~6단계, 수업 · 보강 · 변형 · 회화 카드 · 알파벳 · 토리 이야기)를 만드는 순서 · 묶음 · 표본 · 하루 생산량 측정 · seed/manifest 기록이 실제로 돌아가는 절차인지. 한 영역 × 단계를 한 설정 · 한 프롬프트 판으로 만드는 규칙을 세션에서 어떻게 지키는지. 볼트 기록 훅 예외를 plan 으로 미룬 것이 맞는지. 풀이 검사(Sonnet 일반 API, 약 50달러)의 절차와 비용.
- 검증: 6.4 의 단계 분포 경고 · '덮는다' 정의 · 회화 카드 검사(힌트 문장 · 새 단어가 아이 차례에) · 표본 검토 규칙이 검증기로 만들 수 있을 만큼 정해졌는지. 회화 카드의 힌트 문장이 1~2단계 2~3개 · 3단계 틀 + 단어 3~4개로 충분한지(아이가 말할 수 있는 다른 답을 토리가 받는 길).
