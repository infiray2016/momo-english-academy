### 위험한 곳 둘

**(가) 감시 타이머.** 끝 안 옴 상한은 글 길이 ÷ (8 × 빠르기) + 5초다. 8 글자/초는 보통 TTS 의 절반쯤이고, 읽기 줄 · 지문은 문장마다 발화를 나누므로(speech.sentence_pause_ms) 긴 지문도 문장 단위로 잰다. 그래서 정상 발화를 끝 상한이 먼저 끊을 일은 보이지 않는다. 시작 안 옴 3초는 실측이 없어 ⚠️ 로 남는다(L-8, 브리프가 말한 C148 은 인식 쪽 관찰이라 읽어 주기 시작 지연의 근거가 되지 못한다). 포기 뒤 정리는 맞다: `giveUp` 이 `settleIfCurrent` 로 한 번만 끝내고(`browser.ts:488-494`), `synth.cancel()` 은 소비자의 then 보다 먼저 동기로 돈다. 그래서 다음 듣기 · 다음 읽기와 겹치지 않는다. 늦게 온 start · end · error 는 `speaking !== current` 로 걸러진다. 기록 'timeout' 은 남지만 듣기 요약이 이것을 '끝'으로 읽는다(M-2).

**(나) R1 경합.** 말하기 누름 → 읽기 멈춤 → 듣기는 맞다. 1~3단계 바로 보내는 턴은 `submit` 이 다시 `queue.cancel()` 한다(`talk-frame.tsx:620`). '그만'은 `stop` 이 읽기를 멈추고, '더 이야기하기'는 읽기 뒤에 이어 붙인다. 인사 끝 턴은 pending 이 없어(`flow.ts:702-719`) 따라 말하기 전에 아이 차례가 잘못 열리지 않는다. e2e 의 `untilChildTurn` · `data-talk-reading` · `:not([data-speak-waiting])` 고침은 맞게 읽힌다. 남는 경합은 힌트 문장 듣기(I-1), 이어 붙인 말풍선의 typedDone(M-1), 목표 턴 칭찬(M-4)이다.

**I-1. R1 로 아이 차례가 읽는 중 열리면서, '힌트 문장 듣기'를 누르면 힌트가 들리지 않고 선생님 읽기가 이어진다.**
- 무엇이: 힌트 듣기 단추는 음성 접점의 `speak` 를 바로 부른다(`child-turn.tsx:429-434`). 접점은 선생님 줄의 지금 발화를 cancelled 로 끝내는데(`browser.ts:440`), 줄은 cancelled 를 받아도 세대가 그대로라 다음 문장을 쉼 없이 읽는다(`tori.tsx:459-474`, `pauseLeftMs` 는 endedAt 이 없으면 0 — `pace.ts:52`). 그 `speak` 가 힌트 발화를 바로 끊는다. 말하기 단추만 `onListenStart → queue.cancel()` 을 거친다(`talk-frame.tsx:1165-1168`).
- 왜: 전에는 아이 차례가 읽기 끝 뒤에만 열려 이 길이 없었다. R1 뒤에는 재질문처럼 여러 문장을 읽는 동안(UX 검토 U7-2, 10초 넘게) 아이가 힌트를 열고 듣기를 누를 수 있다. 그러면 누른 소리 단추가 소리를 내지 않는다. 브리프가 따로 보라고 한 '(나) R1 경합'의 새 길이다.
- 어떻게: 힌트 듣기 전에 틀의 읽기 줄을 멈춘다. 예를 들어 ChildTurn 에 `onHintListen`(틀이 `queue.cancel()`)을 두거나, 힌트 문장을 `queue.replay([hint])` 로 읽게 한다. 단위 시험 하나(읽기 줄이 도는 중 힌트 듣기 → 줄이 멈추고 힌트가 마지막 발화)를 더한다.

**I-2. U5-4 안내 '잘 안 들려서 다음으로 가요'가 그 뒤에 일어나는 일과 반대다.**
- 무엇이: `child-turn.tsx:53-54` 의 문구 뒤에 말소리 없음 '모름'을 보낸다(`:338-349`). 정본 3.3 막힘 문단은 '모름'이면 "선생님은 답 예시를 말로 들려주고 같은 질문을 다시 묻는다"고 하고, 다음 질문으로 넘어가는 것은 같은 질문에 talk.dontknow_max 번 '모름'일 때뿐이다(`specs/02-2-세션과-단계표.md:129`).
- 왜: 아이는 '다음으로 가요'를 본 뒤 같은 질문을 다시 듣는다. U5-4 가 고치려던 '왜 같은 질문을 또 하는지 모름'(UX 검토 3판 `ux-review-report.md:120` · 불편 장면 5)을 오히려 키운다. 구현자는 브리프 A 항목 5 의 '꼴'을 글자 그대로 썼으므로 구현 잘못이라기보다 문구 결정이 필요한 자리다(컨트롤러 판단).
- 어떻게: 3.3 의 다음 일과 맞는 문구로 바꾼다. UX 검토가 낸 꼴은 '말소리가 안 들려서 [이름](이/가) 도와줄게요'다. 이름을 채우면 기존 `TEACHER_TEXT` 의 이름 채움을 쓴다. 바꾼 문구를 단위 · e2e 상수에 함께 반영한다.

**M-2. 듣기 요약이 감시 'timeout' 을 읽기 끝으로 읽어, 시작 안 옴 뒤의 듣기를 '읽는 중 끊고 들음(cut)'으로 적는다.** `listen-log.ts:77-79` 는 start 가 아닌 speak-event 를 모두 speak-end 로 바꾸고, `speakRelationOf`(`:89-104`)는 start 가 없으면 cut 을 낸다. 시작 안 옴 포기(`browser.ts:491`)는 start 가 없으므로 다음 듣기의 tc 가 cut 이 된다. C149 가 가르려는 '읽기 끊고 들음'과 감시가 살린 턴(C53 (5) '감시 타이머로 살아난 턴은 따로 적음')이 섞인다. timeout 을 따로 읽거나 적어도 cut 으로 세지 않게 한다.

**M-3. 회화 따라 말하기 · 정리 중 막힘에서 '다시 해 볼래요'가 같은 차례가 아니라 쪽을 연 때의 차례로 돌아간다.** 막힘 화면이 판을 통째로 바꾸므로(`talk-frame.tsx:951-976`) FollowAlong 이 사라졌다가, 풀린 뒤 `at=0`(`follow-along.tsx:456`)으로 쪽을 연 때의 `view.follow.done`(`talk-frame.tsx:889-898`)에서 다시 시작한다. 저장은 차례별 고정 id 라 겹쳐 쌓이지 않는다(`follow-along.tsx:358-365`, `onConflictDoNothing`). 그래도 아이는 이미 한 낱말을 되풀이한다.
