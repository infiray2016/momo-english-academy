- ✅ 세션 상태: 고르기는 활동이 아니다. 활동 번호 · 시도를 바꾸지 않고(e2e 가 활동 번호 1 · 시도 0 을 봄), 틀의 '다음'은 숨긴다(ownButtons).
- ✅ 고른 뒤: TeacherChoice 의 onChosen 이 router.refresh 를 부른다. 세션 틀은 teaching 을 state 가 아니라 view prop 에서 그때그때 읽으므로 새 선생님으로 다시 그려진다. 음성 접점 효과(:702~713)는 view.config.speech 가 새 객체라 다시 돈다. 잠금 풀기는 window.speechSynthesis 문서 단위(WebKit '누름 처리 중의 speak()')라 접점이 바뀌어도 풀림은 남는다.
- ✅ 회화 틀 · TeacherChoice · 선생님 고르기 액션은 고치지 않았다. talk-frame(01:02) · teacher-choice(01:57) · server/teacher(10-23)의 수정 시각이 마-2 보다 앞서고, '마-2' 흔적이 0 건이다. 문구는 TEACHER_TEXT 그대로라 새 글이 없다.
- ✅ 잠금 풀기: unlockSpeechInDocument(`src/lib/speech/unlock.ts`)는 소리 없는 글(" " · 크기 0)을 window.speechSynthesis 에 한 번 읽을 뿐이다. 발화 결과 · 감시 · 접점의 unlocked 셈을 건드리지 않으므로 마-1 · 0-라 규칙 안이다. API 가 없거나 던지면 false 로 삼켜 수업 시작을 막지 않는다. useLessonStart.start 는 첫 await 앞(:100~101)에서 부르므로 누름 처리 안이다.
  - 홈 카드 · 결과 '다음 수업' · 지난 수업 · 회화 마무리 '다음 이야기'도 같은 훅이라 같이 불린다. 소리 없는 한 마디이고 speak 는 줄을 세울 뿐 다른 읽기를 끊지 않으므로 해가 없다.
  - 고르기 화면의 onClickCapture → 접점 unlockFromGesture 는 접점의 unlocked 셈으로 첫 누름에 한 번만 읽는다. 그래서 '인사 듣기'와 겹쳐 같은 소리를 두 번 내거나 끊는 일이 없다.
  - 새로 고침 · 이어 하기 길(감시가 단추를 밝힘)은 바꾸지 않았다.
- ✅ 설정값: 고르기 화면의 빠르기는 speakRateOf(level, speech)이고 숫자 고정이 없다.
