Android Chrome · 데스크톱은 동작만 본다(C130). iPad Safari 에서 읽어 주기 감시(시작 · 끝 알림이 없는 발화가 감시 상한 뒤 넘어가는지, speech.speak_start_timeout_seconds · speech.speak_end_timeout_extra_seconds · speech.speak_chars_per_second 잠정값)와 감시 결과 셋(들려줌 · 끝 알림 없음 · 들려주지 못함)의 가름('끝 알림 없음'을 들려줌으로 보는 가정 포함), 들려주지 못함의 '다시 듣기', '시작!' 아래 무음 모드 한 줄, 막힘 화면 '다시 해 볼래요'(마이크를 다시 켠 뒤 같은 자리로 오는지), 따라 말하기 읽는 중 단추의 N0 세 조건(읽기 끝 2초 뒤 · 0.5초 안 · 읽는 중 누름, C166 R2)을 본다. 결과로 잠정값과 따라 말하기 단추 꼴을 13절에 확정한다. 세 영역 수업(C184)은 iPad 의 기기 한국어 목소리 목록 · 선생님 높이를 얹은 한국어 줄 · 무음 모드에서의 한국어 읽어 주기 · 첫 화면 잠금 풀기를 보고, 기기마다의 한국어 목소리 목록을 이 점검 기록에 남긴다. iPad 버리는 듣기(7절, C213)는 speech.discard_mode ios 로 켠 프리뷰에서 요청자 iPad 로 3단계 회화 수업 하나(인사 → 짧은 준비 → 대화 → 정리, 15분 안팎, 시작 전 45초 넘게 쉼)를 하고 점검표 열두 항목(분석 task-mic-probe-analysis-report.md 10.20.7)을 적는다. 항목은 첫 차례(버림 없음) · '말하기 → 한 번 더 눌러 멈춤 → 선생님 말 → 다시 말하기' 다섯 번 넘게 · 진짜 전체(교대 10턴 결과 10 · 멈춤 0, C53 (5), 감시 타이머로 살아난 턴은 따로) · 버림 전체 · 선생님 목소리 끊김 · 굳음 · 읽는 중 누름 · 다시 말하기와 마이크 안 잡힘 회복(힌트 문장 듣기 뒤 진짜 포함) · 소리 종류별 낱말 인식 · 버림 글이 어디에도 없음 · 쪽 숨김 · 안전판 셈 · 오류와 체감(주황 표시 · 배터리)이다. 항목 12 에는 기다림 셋(선생님 말 뒤 · 버림이 막 열렸을 때 · '다시 말하기' 뒤)의 체감을 적고, client_listen 의 '그 앞 버림' 갈래 · 끝 까닭 칸으로 spec 이 분석 밖에서 정한 갈래(우려 7)를 센다. 항목 1 · 2 · 3 · 5 · 9 가 통과해야 하고(못 채우면 실패 턴의 갈래 · 끝 까닭으로 원인을 찾아 fix 3회까지), 결과로 speech.discard_* 잠정값을 13절에 확정한다(AC-24a) | 수동 점검표 |
| 사용 시험 | 실제 태블릿에서 말하기 · 회화 영역 1회씩. 아이와 1주일 사용 후 설정값을 조정하고, 시드 수업 표본(6.3)을 부모가 읽어 난이도를 체감으로 확인한다. 4주 뒤 숙달 기준값 · 단원 틀 · 세션 시간 · 회화 참고 턴 수(15 · 20 · 25)와 토막 시간 · 말하기 분량 · 아이 화면 글자 크기 · 비용 · 응답 시간을 다시 본다. 복습 카드 종류별 한 장 시간, 하루 복습 시간, 네 영역 세션 시간의 합을 재어 NFR-1 의 하루 시간(낮은 단계 약 35분, 높은 단계 약 55분)과 견준다. 넘으면 session.length_factor 를 다시 본다. 회화가 길면 level_specs 의 참고 턴 수를 새 개정으로 바꾼다(12절 다시 만드는 키, 컨트롤러 결정 C25). 영역별 단원 진도 속도를 견준다. placement.start_level 을 2로 낮출지 본다. 회화 단계 평가의 통과율과 턴마다 쓴 힌트 단의 분포, 1~3단계 회화 단원이 부모 확인으로 넘어간 비율, 대화 기록에서 부모가 본 '스스로 쓴 단어'와 AI 기록의 차이, 다시 하기에서 생긴 '말했다' 비율, 회화 말이 듣기 끝 시간에 끊긴 비율, 회화 2단계의 '모름' 비율(1단계 선택지 들려주기가 없어지는 턱)과 회화를 4단계에서 처음 연 프로필의 첫 다섯 수업 '모름' 비율(컨트롤러 결정 C43)을 잰다(4회차 A4-18 · A4-31 · C7). ai_calls 로 프로필 하루 최대 호출 수와 가정 하루 최대 비용을 재어 하루 안전 상한과 견주고, 상한에 든 날 수를 적는다(컨트롤러 결정 C48). 결과 말 2초(ui.auto_next_seconds) · 칭찬 3초(talk.teacher_praise_seconds)의 체감과, 홈 카드의 단원 진행 5칸 · 진행 막대를 수업 목록 위 띠로 옮긴 뒤 아이가 쌓임을 덜 보는지(3.5 동기 요소)를 본다(C166 R4 · C178). 수행 근거(3.8)는 측정 일곱을 더한다: U 비율과 사유, 정답 노출 · 선택지 · 질문 속 단어 사용 비율, 반복 · 새 예시 · 응용의 비율, 최고와 최근의 차이 · 다시 확인과 복습 필요의 수, 평가 보류 수와 같은 날 이어 본 수 · 예비 문항을 쓴 수 · '문항 모자람'과 '부모 조정' 수, AI 가 스스로 썼다는데 '말했다'가 아닌 단어 수, 참여 완료 대비 통과 실적 대비 목표 달성. 회화 재설계(C189)는 카드 자리 되돌림 비율, 받침 단계와 바닥선의 빈도, 들리지 않음 비율(기기별), 따라가기 턴 수와 돌아온 비율, 참여 완료까지의 말 주고받기 수와 시간, 끝난 길마다의 비율(마무리 물음 · 마무리 제안 뒤 '그만하기' · 바닥선 · '그만하기' · 확인 뒤 중단)과 '그만하기'까지의 말 주고받기 수, 마무리 제안 턴의 위치, 다룬 기회 비율과 이월 크기 · 이월 알림 길이, 아이가 보인 능력 연결 · 확인 보류 수와 사람 판정의 일치, 진도 막힘 후보(입문자가 성실히 참여해도 유효 수행 턴이 모자라 후보 셈이 최소 수업 수에 못 닿는 단원), 후보 셈 문턱(talk.valid_turns_ratio), '말함' 80% 에 닿는 학습일 수, 1~3단계 회화 한 대화의 비용(NFR-2), 회화 설정 기본값(12절)을 잰다(AC-15z). 사람 판정 기준표(3.8)는 사용 시험 시작 전에 요청자가 승인한다. 세 영역 수업(C184)은 수업 설계 지표(스스로 해냄 · 혼자 첫 시도 정답률 · 같이 해 보기 첫 시도 정답률 · 자리별 걸린 시간)와 세 영역 세션 시간(NFR-1 상한, 넘으면 3.3 의 줄이는 차례), 다시 하기 걸린 시간, 'Yes, they do.'만 쓰는 아이 비율, 짝 판정과 사람 판정의 견줌, 선생님 한국어 목소리의 어색함(어색하면 speech.read_ko 를 끈다)을 본다(AC-22o · AC-N18) | 수동(사용 기록 · ai_calls 조회 · 점검표) |
| 병행 검증 | 수행 근거(3.8 의 A7)를 두 절차로 검증한다. 합성 사례(계산 규칙 검증)는 1-가 P12 시험과 함께, 규칙을 고칠 때마다 학습 설계자가 쓰고 요청자가 표본을 확인한다. 사람 판정과 기대값을 사례를 돌린 커밋보다 앞 커밋에 두고, 계산이 기대값과 같은지만 말한다(AC-21g). 사용 시험(교육적 정확성 확인)은 1-나 운영 뒤 4주 동안 judge_first 로 부모가 먼저 적은 사람 판정과 검토 근거로 새 근거와 옛 판정을 견주고, 소수 사례 조건과 정당한 U · 부당한 보류의 구분을 지킨다. 회화 단원은 통과 실적(운영, 참여 완료) · 후보 셈(유효 수행 턴) · 최소 수업 수를 나란히 보이고 '진도 막힘 후보'를 표시하며, 아이가 보인 능력의 '확인 보류' 턴을 사람 판정 사례에 넣는다(3.8, AC-15z, C189). 보고는 요청자에게 가고, 운영 반영은 13절 결정 뒤 새 변경 단위다 | 단위 + 보고 스크립트 + 수동(사람 판정 · 사례 내보내기) |
| 백업 복원 점검 | 석 달마다 최신 백업을 개발용 DB 에 따로 만든 스키마에 복원해 테이블별 행 수를 운영 DB 와 견주고, 같은 작업 안에서 그 스키마를 지운다. 점검이 끝나면 개발용 DB 에 복원한 행이 0 이다(4회차 B4-22, 컨트롤러 결정 C26) | GitHub Actions 수동 작업 + 점검표 |

컴포넌트 단위 테스트는 따로 두지 않고, 화면 동작은 Playwright 로 확인한다.

GPU 없는 머리 없는 Chrome 은 M139 부터 소프트웨어 WebGL 로 저절로 넘어가지 않아 WebGL 맥락을 만들지 못하고, `--enable-unsafe-swiftshader` 깃발을 주어야 한다(Chromium 문서 'Using Chromium with SwiftShader' · Chrome Enterprise 정책 EnableUnsafeSwiftShader, 2026-10-23 확인 — 우리 CI 러너에서 되는지는 구현하며 확인). 그래서 회화 선생님 화면 흐름은 기본 프로젝트가 WebGL 을 끈 채 대신 표시(초상) 길을 늘 시험하고, 3D 프로젝트가 그 깃발로 돈다. 3D 프로젝트가 러너에서 WebGL 을 못 만들면 건너뛰지 않고 실패로 보고한다. 3D 시험 모델은 시험용 작은 VRM(허용된 것)이나 제공 길의 줄인 파일이고 plan 이 정한다(C130).

## 11. 구현 차수

학습 규칙은 모두 첫 운영 배포에 들어간다(요청자 결정 S4). 첫 운영 배포까지의 개발은 두 묶음으로 나눈다(요청자 결정 S8). 1-가가 끝나면 개발용 DB 의 프리뷰 배포로 요청자가 먼저 써 본다. 운영 배포는 1-나와 1~6단계 시드가 다 찬 뒤 한 번 한다. 1-가 프리뷰의 학습 기록은 운영 DB 로 옮기지 않는다. 아이의 매일 학습과 성공 기준 측정은 운영 배포 날부터 센다(4회차 A4-23).
