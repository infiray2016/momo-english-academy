## 7. 음성 처리

음성 인식과 읽어 주기는 브라우저 Web Speech API 를 쓴다. 비용이 없고, 품질이 부족해지면 교체할 수 있도록 인식과 합성을 각각 인터페이스 하나 뒤에 둔다. 녹음은 하지 않는다(2026-10-15 잠정 결정).

회화에서 선생님의 말은 검사를 통과한 문장부터 바로 읽어 준다(6.4). 읽어 주기는 영어 말(tori_en), 1~3단계 소리 줄(따라 할 말 · 선택지), 앱이 붙인 카드의 말(대화 첫 질문(1~3단계는 장면 여는 질문, C206), 카드 자리의 카드 질문 · 받침 줄 · 답 예시, 마무리 물음, 끊긴 턴의 카드 질문), 1~3단계 신호 말 한 줄(소리 줄 앞, 지금 턴에만, C207), 상황 줄(C209), 앱 맞장구 한 줄, 짧은 준비 · 바닥선 듣기 활동의 들려줄 말, 정리 토막의 되짚을 말과 끝인사만 읽는다(3.3, C189). 1단계 선택지 둘 사이에는 'Or' 를 읽는다. 아이 말 듣기는 읽어 주기가 끝난 뒤 아이가 말하기 버튼을 눌러 시작하므로 선생님 목소리를 인식하지 않는다. 읽어 주는 동안에도 말하기 버튼을 누를 수 있고, 누르면 읽어 주기를 멈추고 듣기를 시작한다(읽어 주기가 시작하지 않거나 끝나지 않는 기기를 위해, 컨트롤러 결정 C53). 회화 대화 턴도 같다(C166 R1). 따라 말하기는 말하기 버튼 행의 예외를 따른다(C166 R2). 아이는 1단계부터 말로 답한다(3.3, 요청자 결정 R1). 회화도 녹음하지 않는다.

말하기 · 회화는 마이크가 되는 기기에서만 한다(요청자 결정 S7). 마이크를 쓸 수 없는 기기는 음성 인식을 지원하지 않는 브라우저, 마이크 권한을 거부한 기기, 마이크가 없는 기기, iPad 에서 Siri · 받아쓰기가 꺼진 기기다. 그런 기기에서는 말하기 · 회화 카드에 '마이크가 필요해요. 부모님께 말해 주세요'만 보이고 세션을 열지 않는다. 부모 화면에는 알림과 마이크 설정 경로(브라우저 권한, iPad 는 설정의 Siri · 받아쓰기)를 그림으로 보인다. 읽기 · 쓰기는 그대로 한다. 말하기 · 회화 배치 평가는 마이크가 될 때 본다. 마이크 없이 말하기 · 회화를 대신하는 길(듣고 고르기 · 단어 카드, 회화의 자판 입력)은 두지 않는다. 말하는 도중의 일시적 인식 실패(no-speech · 소음)는 아래 '오류' 행대로 다시 말하게 한다.

음성 인식은 브라우저가 제공하는 서비스로 처리한다. Chrome 은 기본적으로 음성을 Google 서버로 보내 글자로 바꾸고, 그 밖의 브라우저에서도 앱이 처리 위치를 보장받을 수 없다. 기기 안 인식(processLocally)은 데스크톱 Chrome · Edge 139 이상에만 있어 태블릿에서는 쓸 수 없다. 앱은 이 처리를 허용하고, 이 문서와 첫 실행 화면 · 부모 화면에서 부모에게 알린다(2026-10-15 잠정 결정). 아이에게는 처음 마이크를 쓸 때 쉬운 말로 알린다(4절 말하기 세션). Anthropic 으로는 쓴 글 · 회화 대화 · 지난 대화 요약 · 인식된 텍스트를 보낸다. 아이 이름은 {NAME} 으로 바꿔 보내고, 관심 주제는 보내지 않는다.

| 인식 언어 | lang 을 en-US(speech.lang)로 고정한다. 페이지 언어가 한국어여도 바꾸지 않는다 |
| 길이 | 한 번에 최대 15초(speech.max_listen_seconds)씩 듣고, 발표처럼 긴 말은 끊어 듣고 이어 붙인다. 회화 8단계부터 한 턴은 talk.max_answer_seconds(30초)까지 듣고, speech.max_listen_seconds 마다 끊어 듣고 이어 붙인다(컨트롤러 결정 C7) |
| 말하기 버튼 | 한 번 눌러 듣기를 시작한다. 듣는 동안 버튼 둘레에 남은 시간이 줄어드는 표시를 보인다. 듣는 동안 버튼 글은 '듣고 있어요'다(두 문장 이상 답의 '다 말했어요'가 이긴다). 듣기마다 소리가 처음 들어오면(soundstart · speechstart) 마이크 표지를 소리 물결 표지로 바꾼다. 따라 말하기(회화 짧은 준비 · 바닥선 듣기 활동 · 정리, 말하기 세션 따라 말하기)는 따라 할 말을 읽는 동안 버튼을 흐리게 두고, 누르면 듣기를 시작하지 않고 '다 읽은 뒤 눌러요'를 보이며, 읽기가 끝나거나 감시가 그 발화를 끝내면 켠다(C166 R2, iPad N0 실측 뒤 다시 본다). 그 밖(회화 대화 턴 · 말하기 질문 답 · 배치)은 읽는 중 누르면 읽기를 멈추고 듣는다(C53 (2)). 말하는 중에 다시 누르면 바로 끝난다. 두 문장 이상 답하는 말하기 활동과 회화 8단계부터는 듣는 동안 버튼 글자가 '다 말했어요'로 바뀐다(컨트롤러 결정 C37). 듣는 동안에는 다시 듣기 · 답 듣기 · 힌트 문장 듣기 단추를 끈다 — 누르면 듣기가 안내 없이 끝나던 일을 막는다(2026-10-29 음성 분석 A2 · N3) 회화 짧은 준비 쪽지 · 정리의 따라 말하기는 읽기가 멈춘 뒤에도 speech.sentence_pause_ms(잠정) 동안 더 흐리게 두었다 켠다 — iPad 사파리가 읽어 주기 직후 마이크를 못 잡는 no-speech 를 막는다(C201, 쉼 동안 누르면 '다 읽은 뒤 눌러요') |
| 듣기를 끝내는 때 | 한 문장 답(따라 말하기, 말하기 1~4단계 질문 답, 배치 평가 따라 말하기)은 중간 결과가 마지막으로 온 뒤 speech.end_silence_seconds.<구간>(1~3단계 3초, 4단계부터 1.5초)이 지나면 앱이 stop 을 부른다. 회화의 한 문장 답(1~7단계 대화와 짧은 준비 · 바닥선 듣기 활동 · 정리의 따라 말하기)은 speech.end_silence_seconds.talk.<구간>(3 · 2.5 · 2 · 2초)을 쓴다(컨트롤러 결정 C7). 두 문장 이상 답하는 말하기 활동(5단계부터의 질문 답과 그림 보고 말하기, 9~12단계 발표와 확인 질문)은 조용함으로 끝내지 않는다. 말하기 버튼('다 말했어요')을 다시 누르거나 활동 시간 상한으로 끝낸다. 회화 8단계부터의 대화는 마지막 중간 결과 뒤 speech.end_silence_seconds.talk_long(5초) 조용하거나, 말하기 버튼('다 말했어요')을 다시 누르거나, talk.max_answer_seconds 에 닿으면 끝낸다(컨트롤러 결정 C37). 회화 단계 평가 대화는 단계와 관계없이 한 문장 답으로 보고 speech.end_silence_seconds.talk.<구간> 을 쓴다. 브라우저가 스스로 인식을 끝내면(Chrome Android 는 continuous 를 무시하고 첫 쉼에서 끝낸다) 앱이 바로 다시 시작해 이어 붙인다(잠정, 검토 3회차) |
| 인식 결과 확인 | 회화는 인식된 글을 아이 말풍선으로 talk.confirm_seconds(2초) 보이고, 그동안 '다시 말하기' · '보내기'를 누를 수 있다. 1~3단계는 인식 글이 그 턴에 연 영어 문장 힌트나 들려준 답(선택지 · 따라 할 말 · 받침의 답)과 talk.hint_read_match 이상 맞으면 기다리지 않고 바로 보낸다. 연 힌트나 들은 답이 없는 턴은 4단계부터와 같이 보낸다. 보낸 뒤에도 인식 글은 말풍선에 남아 대화 기록이 된다(4절, C119 · C164) |
| 오류 | no-speech · aborted · 결과 없음마다 '다시 한 번 말해 볼까요' 같은 안내 문구를 두고, 다시 듣기는 그 활동의 인식 실패 수가 speech.max_retries(3)에 닿을 때까지다(처음 듣기도 실패로 세므로 다시 듣기는 두 번, C83). audio-capture 도 처음에는 이 오류로 보고, 같은 활동에서 세 번 이어지면 '마이크를 쓸 수 없음'으로 둔다. phrases-not-supported · bad-grammar 는 앱이 쓰지 않는 기능의 오류라 '결과 없음'처럼 다시 듣는다(컨트롤러 결정 C53). 그래도 안 되면 말하기 세션은 그 문항을 건너뛰고 점수에서 뺀다. 건너뛸 때(말하기 따라 말하기 · 1~2단계 질문 답 · 회화 짧은 준비 · 바닥선 듣기 활동 낱말 · 정리 줄)는 '이건 다음에 다시 해요'를 speech.skip_notice_seconds 보인 뒤 넘긴다. 배치 평가에서는 예비 문항으로 바꾼다(3.2). 배치 평가의 인식 실패 3회는 한 문항의 두 시도를 합쳐 센다(컨트롤러 결정 C7). 회화는 아이 말풍선 자리에 회색 '못 들었어요'를 바로 보이고 '[이름]에게 잘 안 들렸어요. 조금 더 크게 말해 볼까요'를 보이며 같은 차례를 이어 간다. 그 시도는 턴으로 세지 않는다. 회화 수업에서 같은 질문 자리에 인식된 말 없이 no-speech 로 끝난 듣기가 talk.nospeech_dontknow_count(2)번 이어지면 '말소리가 안 들려서 [이름](이/가) 도와줄게요'를 같은 시간(speech.skip_notice_seconds) 보인 뒤(C167 (4)) 입력 '모름'(출처 nospeech)으로 보내 들리지 않음 차례가 된다(3.3). 들리지 않음은 기기 쪽이라 받침 · 바닥선 셈에 들지 않고, 선생님이 못 들었다고 말하고 답을 한 번 들려준 뒤 다음 이야기로 가며, 근거는 기술 오류(U)다(C172 가 · C189). iPad 의 Safari · Chrome(WebKit)은 말소리가 없으면 스스로 no-speech 를 내지 않고, 앱이 듣기를 멈추면 aborted('No speech detected')로 끝낸다. 앱은 모은 글이 없을 때 이것을 no-speech 로 본다(컨트롤러 결정 C148, 실측 2026-10-22). 평가 턴은 '모름'으로 보내지 않는다(3.2). audio-capture · aborted · 결과 없음이 성공 없이 여섯 번(speech.max_retries 의 두 배) 이어지면 세션을 진행으로 둔 채 막힘 화면('마이크가 잘 안 돼요', 아래 '막힘 화면' 행)을 보이고, 부모 화면에 '마이크가 멈춤' 알림을 만든다(잠정, 검토 4회차). no-speech 는 이 수에 넣지 않는다. no-speech 로만 끝난 질문(회화에서 들리지 않음으로 닫힌 질문 자리) · 문항(말하기에서 건너뛴 문항)이 같은 세션에서 speech.silent_items_max(3)개 이어지면 막힘 화면('말소리가 잘 안 들려요')을 보이고 부모 알림 '말소리가 들어오지 않음'을 만든다. 알림에는 아이가 말하지 않았을 수도 있다고 적는다(컨트롤러 결정 C22). 단계 평가 문항은 건너뛴 뒤 3.2 의 재시도 · 예비 · 같은 날 이어 보기로 간다. 인식 실패 · 마이크 · 네트워크로 빈 근거는 학습 실패가 아니다(3.8) |
| 감시 타이머 | 인식을 시작한 뒤 speech.max_listen_seconds + speech.watchdog_extra_seconds(3초) 안에 결과 · 오류 · 끝 이벤트가 하나도 없으면, 앱이 인식을 끊고 한 번 다시 시작한다. 또 멈추면 그 세션을 진행 상태로 둔 채 막힘 화면('마이크가 잘 안 돼요')을 보인다. 홈으로 보내지 않는다. 부모 화면에 '마이크가 멈춤' 알림(그 기기의 브라우저 이름과 시각)을 만든다 |

| 그대로 되는 것 | AI 없이 되는 것은 그대로 한다. 읽기, 쓰기 1~3단계, 따라 말하기, 듣기, 복습, 배치 평가, AI 가 필요 없는 수업의 다시 하기, 선생님 이야기다. 말하기 1~2단계 세션은 질문 답까지 그대로 한다(앱이 판정, 컨트롤러 결정 C38). 3~8단계 세션은 따라 말하기 · 듣기만 하고 질문 답을 건너뛴다(3.7 의 a = 1). 그 점수는 최근 성적에 넣지 않는다(3.7, 최소 수업 수에는 넣는다). 세 영역 1~3단계의 새 자리(오늘 배울 것 · 보여 주기 · 같이 해 보기 · '왜' · 짝 · 되짚기)는 AI 를 부르지 않으므로(선생님 말 · 본보기 · '왜'는 시드나 앱 문구, 같이 해 보기 · 짝은 앱 채점) 읽기 · 쓰기 1~3단계 · 말하기 1~2단계 세션은 여섯 자리를 다 한다. 말하기 3단계 세션은 혼자 질문 답만 그 앞 이야기 화면과 함께 건너뛰고, 건너뛴 질문의 짝도 내지 않는다(되짚기 셈에서 U, C184). 말하기 9~12단계 세션은 시작하지 않는다 |

| AI 호출 하나의 실패 · 지연 | 대화형 호출은 타임아웃 10초, 재시도 1회다(앱이 첫 바이트 전 연결 오류에만 한다. | 다시 보내도 같은 오류 | 400(콘솔 한도가 아닌 것) · 404 · 413 과 모델 은퇴로 실패한 요청은 다시 부르지 않고 'AI 호출 하나의 실패'로 처리하며 이어진 실패 수에 더하지 않는다. 같은 호출 목적에서 이 오류가 한 학습일에 ai.down_after_failures 번 나면 부모 알림 '호출 설정 확인 필요'(호출 목적 · 모델 · 오류 코드)를 그날 한 번 만든다(컨트롤러 결정 C17) |
| 회화 턴 실패 | 선생님의 첫 문장을 보내기 전에 연결 오류 · 타임아웃이 나면, 앱이 아이의 같은 말로 한 번 다시 부른다. 그동안 선생님 말풍선에 기다림 표시를 보인다. 1~3단계는 다시 실패해도 대화를 끊지 않는다. 선생님 반응 자리에 카드의 안전한 대사(뜻 있음, 턴 번호로 돌림)를 보이고 그 턴을 카드 자리로 보아 가장 앞의 남은 기회의 카드 질문을 붙인다(3.3). 칭찬 대사는 시드에 뜻 칸이 없어 이 자리에 쓰지 않고, 아이 말이 모름 · 못 알아들음 꼴('Huh?' · 'I don't know.')이면 안전한 대사 대신 받침 둘째(쉬운 질문) 자리의 시드 상황 줄을 쓴다(2026-11-07 fix r1). 다만 1~3단계 상황 차례(인사 끝 · 받침 · 들리지 않음)에서는 안전한 대사 대신 그 자리의 시드 상황 줄을 쓰고, 계획의 붙일 줄(받침 줄 · 답 소리 · 다음 기회)은 그대로 붙이며, 인사 끝 뒤에는 카드 질문을 붙이지 않는다(3.3 상황 차례, C19 · C209). 그 턴은 '말했다'를 세지 않고, 실패는 'AI 쉬는 중'의 이어진 실패 수에 더한다(4회차 A4-28). 1~3단계에서 응답이 막힘 참이고 tori_en 만 빈 글이면 실패로 보지 않고 반응이 지워진 막힘 차례로 받아, 다시 부르지 않고 반응 자리에 받침 자리의 시드 상황 줄을 둔 뒤 계획의 답 소리 · 신호 말(받침 둘째면 쉬운 질문)을 붙이며 기술 오류 자리로 세지 않는다(ai_calls 는 검증 실패 · empty_tori_en_stuck, 컨트롤러 결정 2026-11-07 장부 T-244). 4단계부터는 다시 실패하면 선생님이 앱에 둔 고정 대사 'Oops, I need a little break!'(4단계는 '나 잠깐 쉬어야 해!'를 함께, 카드 칸이 아니다 — C93)를 말한다. 그리고 '여기까지 이야기한 것은 저장했어요. 다음에 이어서 해요'를 보인 뒤 수업 목록으로 간다. 끝맺음 턴은 부르지 않는다. 참여 완료 전이면 세션은 진행으로 남아 이어 할 수 있고, 참여 완료 뒤이면 이미 끝낸 수업이다(3.3). 거절은 같은 모델로 다시 부르지 않는다. Haiku 5.5 거절은 첫 문장을 보내기 전일 때만 Sonnet 5.5 로 한 번 다시 부른다(6.1). 첫 문장 뒤의 거절은 아래처럼 보낸 문장을 두고 턴을 닫는다(4회차 B4-16). 다시 부른 모델도 거절하면 선생님은 카드의 안전한 대사를 말하고 대화를 이어 간다. 1~3단계는 그 턴을 카드 자리로 보아 카드 질문을 붙인다(상황 차례는 위와 같이 상황 줄과 계획의 붙일 줄, 모름 꼴 아이 말 뒤는 받침 둘째 상황 줄). 첫 문장을 보낸 뒤 스트림이 끊기거나, 타임아웃이 나거나, stop_reason 이 refusal 이나 max_tokens 로 끝나면 보낸 문장은 그대로 둔다. 그 턴을 닫는다. 모든 단계에서 보낸 문장에 물음표로 끝나는 문장이 없으면 그 턴을 카드 자리로 보아 앱이 가장 앞의 남은 기회의 카드 질문을 붙여 보이고 읽어 주고, 다음 턴 힌트는 그 카드 항목의 힌트로 채운다(컨트롤러 결정 C19, 1~3단계는 C189 로 같은 길). 보낸 문장에 질문이 있으면 그 턴의 카드 항목을 알 수 없으므로 '힌트' 버튼을 보이지 않는다. 같은 질문을 되풀이하지 않는다. 서버 측 대체 모델 재시도가 스트림 중간에 일어나면 fallback 블록 뒤의 text 블록을 앞 text 블록에 이어 붙여 하나의 JSON 으로 푼다 |
| 1~3단계 AI 질문이 검사에 걸림 | 걸린 질문 문장은 화면 · 읽어 주기 · 응답 본문에서 빠지고 그 턴은 카드 자리가 된다(가장 앞의 남은 기회의 카드 질문을 붙이고, 막힌 뒤면 받침 줄을 붙인다, 3.3 · 6.4). 같은 질문 되풀이(3.3 되풀이 막기)로 지운 질문도 같은 길이다. 호출 실패가 아니므로 'AI 쉬는 중'의 이어진 실패 수에 더하지 않는다(C189) |
| 끝맺음 없이 떠난 대화 | 3.3 '대화가 멈추는 경우' 표와 5절 전이 표를 따른다. 앱 진입은 홈 화면 요청이다. 선생님의 말이 없는 마지막 턴이 있으면 같은 시도 id 로 다시 받는다. 정리(요약을 받는 끝맺음 턴)가 두 번 실패하면 요약 없이 닫는다(컨트롤러 결정 C17) |
| 대화 안전 상한 | 대화 하나가 talk.safety_max_turns 에 닿으면 선생님이 '새 이야기로 이어 가자' 끝인사로 닫고 수업 목록으로 간다. 같은 학습일에 talk.safety_alert_count 번째로 닿을 때 부모 알림을 만든다(3.3) |
| 첨삭 대기 | 초고를 제출하면 그 첫 세션은 끝난 것으로 센다(연속 일수). 수업은 둘째 세션을 끝내야 끝난 것이고 별도 그때 붙는다(3.5). 첨삭이 실패하면 attempts 에 '첨삭 대기'로 두고 다음 앱 진입 때 다시 부른다. 첨삭이 오면 홈에 '첨삭이 왔어요' 포스트잇을 붙이고 그 수업의 점수를 채운다. 수업 목록에는 그 수업이 '첨삭 보기'로 놓이고, 아이가 고르면 둘째 세션으로 열린다. 둘째 세션을 열 때 첨삭이 없으면 그 자리에서 다시 한 번 부른다. 그래도 없으면 '아직 글을 살펴보고 있어요'를 보이고 수업 목록으로 돌아간다. 'AI 쉬는 중'에는 부르지 않고 기다린다. 거절이 아닌 까닭으로 같은 초고의 첨삭이 ai.feedback_max_attempts(5)번 실패하면 '첨삭 못 함'으로 두고 부모에게 알린다(컨트롤러 결정 C17) |
| 안전 분류기 거절 | 'AI 호출 하나의 실패'와 같이 처리하고 기록한다. 같은 입력이 거절로 두 번 끝나면 그 입력으로는 더 부르지 않는다. 첨삭이면 그 초고를 '첨삭 못 함'으로 두고 부모에게 알린다. 그 수업은 끝내지 않은 수업으로 남아 다시 고를 수 있고, 다시 고르면 새 초고를 쓴다(잠정, 검토 3회차). 거절은 'AI 쉬는 중'의 실패 수에 더하지 않는다 |
| 실시간 응답 검증 실패 | 6.1 의 규칙대로 1회 다시 요청하고 정규화한다. 필수 필드가 없으면 'AI 호출 하나의 실패'와 같이 처리한다 |
| 시드 빈 칸 · 검증 실패 | 시드 완전성 검사(6.3)가 CI 에서 실패하면 배포하지 않는다. 앱은 실행 중에 수업을 만들지 않으므로 아이 화면에 수업 생성 실패 경로가 없다. 진행 중 단원은 단원의 시작 개정 안에서 가장 높은 정정 판을 읽는다(5절) |
| 다음 단계 시드가 없음 | 단계 평가를 통과했지만 다음 단계가 seed.complete_through_level 보다 높으면 '다음 단계 준비 중'으로 둔다(3.2). 세션 시작 서버 액션은 시드 범위 밖 단계의 수업을 열지 않는다 |
| 근거가 얇은 단계 평가 | 기술 오류(인식 실패 · 마이크 · 말소리 없음 · 들려주지 못함 · 네트워크 · AI 채점 실패 · 'AI 쉬는 중')로 채점하지 못한 문항이 남으면 3.2 의 잠재 점수(최저 S · 최고 S + R)로 통과 · 미통과 · 보류를 가른다. 답을 받지 못한 문항은 세션 끝 재시도 → 같은 단원 · 같은 유형 예비 문항으로 메우고, 그래도 남아 보류면 까닭이 풀린 뒤 같은 학습일에도 '평가 이어 보기'로 모자란 문항만 본다. AI 과제 문항은 첨삭 대기처럼 기다렸다가 저장된 원래 답안을 다시 채점하고 아이에게 다시 시키지 않는다(새 작문은 3.2 '새 작문의 조건'일 때만). 예비가 모자라면 다른 벌을 빌리지 않고 '문항 모자람'으로 닫은 뒤 새 벌로 다시 본다(3.2 복구 경로). 보류에는 부모 알림 '평가 보류' 하나를, 문항 모자람에는 '평가 문항이 모자라 새 벌로 다시 봐요'를 만든다(4절). 보류는 재응시 간격 · 보강 · 부모 확인에 들지 않는다 |
| 마이크를 쓸 수 없음 | 말하기 · 회화 카드를 닫고 부모 화면에 알린다(7절). 읽기 · 쓰기는 그대로다 |
| 네트워크 끊김 | 진행 중 세션의 답만 기기에 쌓는다. 시도마다 기기가 만든 id 로 서버에 보내고, 같은 시도 id 는 한 번만 저장된다. 완료된 세션은 서버 기록을 따른다. 1~2차는 PWA 가 아니므로 끊긴 상태에서는 앱을 새로 열 수 없다 |
| 앱 오류 | 아이 화면에서 잡히지 않은 오류가 나면 앱 오류 화면('잠깐 문제가 생겼어요', 큰 '다시 해 볼래요', 작은 '홈')을 보인다. '다시 해 볼래요'는 그 화면을 다시 그린다. 세션 · 회화는 진행으로 남으므로 다시 그리면 같은 활동에서 이어진다. 없는 주소이거나 열 수 없는 세션이면 '찾는 화면이 없어요'와 큰 '홈'이다(돌아갈 자리가 없는 유일한 경우, C178) |
| 복구 예외 | 같은 화면에서 바로 고칠 수 없어 수업 목록을 거쳐 돌아오는 경우는 둘이다. 회화 4단계부터 턴이 두 번 실패한 안내('여기까지 이야기한 것은 저장했어요 …')와 첨삭이 아직 없는 둘째 세션('아직 글을 살펴보고 있어요')이다. 둘 다 진행 중 수업 상태(회화는 세션 진행 · 대화 기록 · 말 주고받기 수 · '말했다' 기록, 쓰기는 제출한 초고와 첨삭 대기 시도)를 보존한다. 수업 목록 맨 위의 이어 하기 자리('하던 수업 이어 하기' · '첨삭 보기', '여기부터 해요')에서 같은 자리로 돌아온다. 회화는 마지막 아이 말의 선생님 말을 같은 시도 id 로 다시 받아 그 턴부터 잇고('끝맺음 없이 떠난 대화' 행), 쓰기는 첨삭이 오면 둘째 세션 처음이다. 홈을 거치지 않는다. 참여 완료 뒤에 난 회화 실패는 이미 끝낸 수업이라 목록의 다음 수업으로 간다. 규칙으로 닫힌 세션(오래 멈춘 세션 · 다른 수업을 골라 중단)과 대화 안전 상한의 닫힘은 이어 할 상태가 없어 복구 예외가 아니다(C179 (4)) |
| 같은 프로필의 동시 사용 | 두 번째 기기에서 같은 영역을 열면 진행 중 세션을 이어 하고 새 세션을 만들지 않는다. 회화의 끝맺음 정리는 마지막 턴에서 talk.idle_close_minutes 가 지난 뒤에만 하므로, 다른 기기의 진입이 진행 중인 대화를 닫지 않는다 |
| 오래 멈춘 세션 | session.resume_hours(24시간)가 지나면 중단으로 닫는다. 그 프로필의 다음 수업 목록 요청 때 서버가 닫는다. 중단은 단원 횟수 · 최근 성적 · 별에 넣지 않고 단어별 정오와 '말했다'만 남긴다. 배치 평가는 닫지 않고 다음에 이어 본다 |
| 승급 오판 | 부모 화면에서 되돌린다. 자동 판정과 되돌림은 progress_events 에 남는다 |
| 기준 미달 반복 | 보강 상한을 넘으면 부모 확인 표시를 띄운다(3.2) |
| 비용 알림 기준 도달 | ai.daily_call_alert · ai.daily_cost_alert_usd · ai.monthly_cost_alert_usd 에 닿으면 부모 메뉴에 알림을 붙이고 부모 화면 첫 줄에 보인다. 아이의 진행과 호출은 그대로다 |
| 부모 알림 | parent_alerts 에 남기고 홈의 부모 메뉴에 점으로 표시한다. 종류는 4절 부모 화면 '알림 목록' 행을 따른다. 내용은 부모 화면 첫 줄에 보인다 |
