## 7. 음성 처리

음성 인식과 읽어 주기는 브라우저 Web Speech API 를 쓴다. 비용이 없고, 품질이 부족해지면 교체할 수 있도록 인식과 합성을 각각 인터페이스 하나 뒤에 둔다. 녹음은 하지 않는다(2026-10-15 잠정 결정).

회화에서 토리의 말은 검사를 통과한 문장부터 바로 읽어 준다(6.4). 읽어 주기는 영어 말(tori_en)과 앱이 붙인 카드의 말(대화 첫 질문, 1~3단계의 카드 질문 · 답 예시 · 1단계 답 두 개, 4단계부터 끊긴 턴의 카드 질문), 정리 토막의 되짚을 말과 끝인사만 읽는다. 1단계 답 두 개 사이에는 'Or' 를 읽는다. 아이 말 듣기는 읽어 주기가 끝난 뒤 아이가 말하기 버튼을 눌러 시작하므로 토리 목소리를 인식하지 않는다. 읽어 주는 동안에도 말하기 버튼을 누를 수 있고, 누르면 읽어 주기를 멈추고 듣기를 시작한다(읽어 주기가 시작하지 않거나 끝나지 않는 기기를 위해, 컨트롤러 결정 C53). 아이는 1단계부터 말로 답한다(3.3, 요청자 결정 R1). 회화도 녹음하지 않는다.

말하기 · 회화는 마이크가 되는 기기에서만 한다(요청자 결정 S7). 마이크를 쓸 수 없는 기기는 음성 인식을 지원하지 않는 브라우저, 마이크 권한을 거부한 기기, 마이크가 없는 기기, iPad 에서 Siri · 받아쓰기가 꺼진 기기다. 그런 기기에서는 말하기 · 회화 카드에 '마이크가 필요해요. 부모님께 말해 주세요'만 보이고 세션을 열지 않는다. 부모 화면에는 알림과 마이크 설정 경로(브라우저 권한, iPad 는 설정의 Siri · 받아쓰기)를 그림으로 보인다. 읽기 · 쓰기는 그대로 한다. 말하기 · 회화 배치 평가는 마이크가 될 때 본다. 마이크 없이 말하기 · 회화를 대신하는 길(듣고 고르기 · 단어 카드, 회화의 자판 입력)은 두지 않는다. 말하는 도중의 일시적 인식 실패(no-speech · 소음)는 아래 '오류' 행대로 다시 말하게 한다.

음성 인식은 브라우저가 제공하는 서비스로 처리한다. Chrome 은 기본적으로 음성을 Google 서버로 보내 글자로 바꾸고, 그 밖의 브라우저에서도 앱이 처리 위치를 보장받을 수 없다. 기기 안 인식(processLocally)은 데스크톱 Chrome · Edge 139 이상에만 있어 태블릿에서는 쓸 수 없다. 앱은 이 처리를 허용하고, 이 문서와 첫 실행 화면 · 부모 화면에서 부모에게 알린다(2026-10-15 잠정 결정). 아이에게는 처음 마이크를 쓸 때 쉬운 말로 알린다(4절 말하기 세션). Anthropic 으로는 쓴 글 · 회화 대화 · 지난 대화 요약 · 인식된 텍스트를 보낸다. 아이 이름은 {NAME} 으로 바꿔 보내고, 관심 주제는 보내지 않는다.

| 항목 | 인식 규칙 |
|---|---|
| 인식 언어 | lang 을 en-US(speech.lang)로 고정한다. 페이지 언어가 한국어여도 바꾸지 않는다 |
| 길이 | 한 번에 최대 15초(speech.max_listen_seconds)씩 듣고, 발표처럼 긴 말은 끊어 듣고 이어 붙인다. 회화 8단계부터 한 턴은 talk.max_answer_seconds(30초)까지 듣고, speech.max_listen_seconds 마다 끊어 듣고 이어 붙인다(컨트롤러 결정 C7) |
| 말하기 버튼 | 한 번 눌러 듣기를 시작한다. 듣는 동안 버튼 둘레에 남은 시간이 줄어드는 표시를 보인다. 말하는 중에 다시 누르면 바로 끝난다. 두 문장 이상 답하는 말하기 활동과 회화 8단계부터는 듣는 동안 버튼 글자가 '다 말했어요'로 바뀐다(컨트롤러 결정 C37) |
| 듣기를 끝내는 때 | 한 문장 답(따라 말하기, 말하기 1~4단계 질문 답, 배치 평가 따라 말하기)은 중간 결과가 마지막으로 온 뒤 speech.end_silence_seconds.<구간>(1~3단계 3초, 4단계부터 1.5초)이 지나면 앱이 stop 을 부른다. 회화의 한 문장 답(1~7단계 대화와 오늘 쓸 말 · 말해 보기 · 정리의 따라 말하기)은 speech.end_silence_seconds.talk.<구간>(3 · 2.5 · 2 · 2초)을 쓴다(컨트롤러 결정 C7). 두 문장 이상 답하는 말하기 활동(5단계부터의 질문 답과 그림 보고 말하기, 9~12단계 발표와 확인 질문)은 조용함으로 끝내지 않는다. 말하기 버튼('다 말했어요')을 다시 누르거나 활동 시간 상한으로 끝낸다. 회화 8단계부터의 대화는 마지막 중간 결과 뒤 speech.end_silence_seconds.talk_long(5초) 조용하거나, 말하기 버튼('다 말했어요')을 다시 누르거나, talk.max_answer_seconds 에 닿으면 끝낸다(컨트롤러 결정 C37). 회화 단계 평가 대화는 단계와 관계없이 한 문장 답으로 보고 speech.end_silence_seconds.talk.<구간> 을 쓴다. 브라우저가 스스로 인식을 끝내면(Chrome Android 는 continuous 를 무시하고 첫 쉼에서 끝낸다) 앱이 바로 다시 시작해 이어 붙인다(잠정, 검토 3회차) |
| 인식 결과 확인 | 회화는 인식된 글을 talk.confirm_seconds(2초) 보이고, 그동안 '다시 말하기' · '보내기'를 누를 수 있다. 1~3단계는 인식 글이 그 턴에 연 영어 문장 힌트나 들려준 답과 talk.hint_read_match 이상 맞으면 기다리지 않고 바로 보낸다. 연 힌트나 들은 답이 없는 턴은 4단계부터와 같이 보낸다(4절) |
| 오류 | no-speech · aborted · 결과 없음마다 '다시 한 번 말해 볼까요' 같은 안내 문구를 두고, 다시 듣기는 그 활동의 인식 실패 수가 speech.max_retries(3)에 닿을 때까지다(처음 듣기도 실패로 세므로 다시 듣기는 두 번, C83). audio-capture 도 처음에는 이 오류로 보고, 같은 활동에서 세 번 이어지면 '마이크를 쓸 수 없음'으로 둔다. phrases-not-supported · bad-grammar 는 앱이 쓰지 않는 기능의 오류라 '결과 없음'처럼 다시 듣는다(컨트롤러 결정 C53). 그래도 안 되면 말하기 세션은 그 문항을 건너뛰고 점수에서 뺀다. 배치 평가에서는 예비 문항으로 바꾼다(3.2). 배치 평가의 인식 실패 3회는 한 문항의 두 시도를 합쳐 센다(컨트롤러 결정 C7). 회화는 '토리에게 잘 안 들렸어요. 조금 더 크게 말해 볼까요'를 보이고 같은 차례를 이어 간다. 그 시도는 턴으로 세지 않는다. 회화 수업에서 같은 질문에 인식된 말 없이 no-speech 로 끝난 듣기가 두 번 이어지면 막힌 것으로 보고 입력 '모름'으로 보낸다(3.3). 평가 턴은 '모름'으로 보내지 않는다(3.2). audio-capture · aborted · 결과 없음이 성공 없이 여섯 번(speech.max_retries 의 두 배) 이어지면 세션을 진행으로 둔 채 '마이크가 잘 안 돼요. 부모님께 말해 주세요'와 '홈'을 보이고, 부모 화면에 '마이크가 멈춤' 알림을 만든다(잠정, 검토 4회차). no-speech 는 이 수에 넣지 않는다. no-speech 로만 끝난 질문(회화에서 '모름'으로 넘어간 질문) · 문항(말하기에서 건너뛴 문항)이 같은 세션에서 speech.silent_items_max(3)개 이어지면 '말소리가 잘 안 들려요. 부모님께 말해 주세요'와 '홈'을 보이고 부모 알림 '말소리가 들어오지 않음'을 만든다. 알림에는 아이가 말하지 않았을 수도 있다고 적는다(컨트롤러 결정 C22) |
| 감시 타이머 | 인식을 시작한 뒤 speech.max_listen_seconds + speech.watchdog_extra_seconds(3초) 안에 결과 · 오류 · 끝 이벤트가 하나도 없으면, 앱이 인식을 끊고 한 번 다시 시작한다. 또 멈추면 그 세션을 진행 상태로 둔 채 '마이크가 잘 안 돼요. 부모님께 말해 주세요'를 보이고 홈으로 간다. 부모 화면에 '마이크가 멈춤' 알림(그 기기의 브라우저 이름과 시각)을 만든다 |
| 마이크를 쓸 수 없음 | 음성 인식 API 가 없거나 not-allowed · service-not-allowed · language-not-supported(그 기기에서 en-US 인식이 안 됨, 컨트롤러 결정 C53) 오류가 나면 그 기기를 '마이크를 쓸 수 없음'으로 본다. audio-capture 는 위 '오류' 행대로 다시 듣고, 같은 활동에서 세 번 이어질 때만 그렇게 본다. 말하기 · 회화 세션이나 말하기 배치 도중에 이렇게 되면 세션(배치는 멈춘 문항)을 진행으로 둔 채 '마이크가 필요해요. 부모님께 말해 주세요'와 '홈' 버튼 하나를 보인다. 말하기 · 회화 카드는 위 문단대로 닫히고, 부모 화면에 설정 경로와 '마이크 다시 확인' 버튼을 보인다(4절). 음성 인식 API 가 없던 기기는 홈 진입마다 다시 확인한다. 권한 거부와 Siri · 받아쓰기 꺼짐은 부모가 그 기기에서 '마이크 다시 확인'을 눌러 푼다. 누르면 권한을 묻고 인식을 한 번 시작해 보고, 되면 그 기기의 상태를 지우고 카드를 연다. 기기 상태는 그 브라우저에만 둔다(잠정, 검토 4회차) |
| 읽어 주기 | en-US 음성을 고르고, 첫 재생은 아이의 버튼 누름으로 시작한다(iOS 의 사용자 동작 요구). 회화는 처음 안내 화면의 시작 버튼 누름과 화면에 들어올 때의 누름을 첫 재생으로 쓴다. 토리 말과 힌트의 {NAME} 은 영어 이름으로 채워 읽는다 |
| 네트워크 | Chrome 인식은 네트워크가 있어야 한다. network 오류가 나면 '인터넷이 끊겼어요. 연결되면 다시 해요'를 보이고, 다시 시도 횟수와 위 여섯 번에 넣지 않는다(잠정, 검토 4회차) |
| 말 사이 쉼 측정 | 하지 않는다(3.7) |

## 8. 오류 처리

AI 를 쓸 수 없는 때는 'AI 쉬는 중' 상태 하나로 다룬다(요청자 결정 S9). 호출 하나가 실패하는 것과, 집 전체가 쉬는 상태로 들어가는 것을 나눈다.

| 'AI 쉬는 중' | 규칙 |
|---|---|
| 들어가는 조건 | 넷 가운데 하나다. (1) 하루 안전 상한(ai.safety_daily_calls · ai.safety_daily_cost_usd)에 닿는다. (2) Anthropic 콘솔 지출 한도 오류(400, 'You have reached your specified … API usage limits')나 조직 상한 오류(429, error_code enforced_spend_limit_reached)를 받는다. (3) 연결 · 서버 오류(연결 실패 · 5xx · 529 · 타임아웃)와 콘솔 한도가 아닌 429 가 성공 없이 ai.down_after_failures(3)번 이어진다(잠정, 검토 3회차). 이어진 실패 수는 앱의 1회 다시 부름까지 실패한 한 차례를 하나로 세고, 회화는 턴마다 센다(컨트롤러 결정 C18). (4) 계정 오류(401 · 402 · 403)를 한 번 받는다. 까닭은 '계정 확인 필요'다(컨트롤러 결정 C1). 다시 보내도 같은 오류(콘솔 한도가 아닌 400 · 404 · 413, 모델 은퇴)는 들어가는 조건이 아니다(아래 상황 표, 컨트롤러 결정 C17). 상태는 ai_status 한 행에 둔다 |
| 동안 | 앱은 확인 호출 밖의 AI 를 부르지 않는다. AI 가 필요한 활동은 시작하지 않는다. 쓰기 4단계부터, 말하기 3단계부터의 질문 답 · 그림 보고 말하기 · 발표, 회화, 생각 꺼내기, AI 문항이 든 단계 평가 세션이다. 그 수업을 고르면 '토리가 잠깐 쉬어요. 다른 공부를 해 볼까요'와 '홈' 버튼을 보인다. 모든 영역이 같은 문구다(4절, 컨트롤러 결정 C16). 하던 활동 도중에 들어가면 그 세션을 진행 상태로 두고 같은 안내를 보인다. 말하기 3~8단계는 예외로, 질문 답을 건너뛰고 세션을 끝까지 한다(4회차 B4-15) |
| 그대로 되는 것 | AI 없이 되는 것은 그대로 한다. 읽기, 쓰기 1~3단계, 따라 말하기, 듣기, 복습, 배치 평가, AI 가 필요 없는 수업의 다시 하기, 토리 이야기다. 말하기 1~2단계 세션은 질문 답까지 그대로 한다(앱이 판정, 컨트롤러 결정 C38). 3~8단계 세션은 따라 말하기 · 듣기만 하고 질문 답을 건너뛴다(3.7 의 a = 1). 말하기 9~12단계 세션은 시작하지 않는다 |
| 첨삭을 기다리던 글 | 그대로 둔다. 풀리면 다음 앱 진입 때 밀린 첨삭을 부른다. 첨삭 전용 규칙은 따로 두지 않는다 |
| 풀리는 조건 | 하루 안전 상한은 다음 학습일에만 풀리고, 확인 호출을 보내지 않는다(요청자 결정 T1). 그 시각이 지난 뒤 ai_status 를 읽는 첫 요청(홈 · 부모 화면 · 카드 누름)이 시각만 보고 푼다(컨트롤러 결정 C46). 나머지는 확인 호출이 한 번 성공하면 풀린다. 연결 장애는 ai.down_retry_minutes(5 · 15 · 30분, 마지막 값으로 계속) 간격으로, 콘솔 한도와 계정 확인 필요는 ai.probe_interval_minutes(60분) 간격으로 보낸다. 콘솔 오류 메시지에 풀리는 시각이 있으면 그 시각이 지난 뒤 첫 앱 진입에서 바로 보낸다. 부모 화면에 보이는 콘솔 한도의 풀리는 시각은 메시지의 시각이고, 없으면 다음 달 1일 09시(한국 시간)다(컨트롤러 결정 C1). 확인 호출이 실패하면 실패 종류로 까닭을 다시 정한다. 콘솔 한도 오류면 '콘솔 한도', 401 · 402 · 403 이면 '계정 확인 필요'로 바꾸고 그 까닭의 간격 · 부모 문구 · 알림을 쓴다. 연결 · 서버 오류 · 타임아웃과 그 밖의 오류면 까닭을 두고 확인 차례를 하나 올린다. 풀리면 이어진 실패 수와 확인 차례를 0 으로 되돌린다(컨트롤러 결정 C17) |
| 확인 호출 | 앱 진입(홈 화면 요청)과 부모 화면 요청 때 다음 확인 시각이 지났으면 서버가 응답 뒤(after())에 하나 보낸다. 간격은 그대로이고 버튼이 아니다(요청자 결정 T1, 컨트롤러 결정 C29). ai_status 행의 다음 확인 시각을 먼저 미루는 데 성공한 요청 하나만 보낸다. 모델은 쉬는 상태에 들게 한 마지막 실패 호출의 모델이고, ai_status 에 '확인 모델'로 남긴다. 콘솔 한도 · 계정 확인 필요가 까닭이면 claude-haiku-5-5 다(한도와 키는 워크스페이스 전체에 걸린다). 설정은 그 모델이 받는 가장 가벼운 조합이다(Haiku 5.5 low · disabled, Sonnet 5.5 low · between_tools, Opus 5.5 low · adaptive). 입력은 아이 정보가 없는 고정 한 단어 'ok'다(컨트롤러 결정 C46). 최대 출력은 1토큰이고, HTTP 200 이면 stop_reason 과 관계없이 성공이다. 6.1 정규화를 쓰지 않는다. ai_calls 에 목적 '확인'으로, profile_id 를 비워 남긴다. 하루 호출 수 · 비용 알림과 안전 상한에 넣지 않는다(컨트롤러 결정 C1) |
| 부모 화면 | 알림과 부모 화면 'AI 쉬는 중' 행에 까닭, 풀리는 시각(한국 시간), 다음 확인 시각, 오늘 호출 수와 비용(호출 목적별 · 세션별)을 보인다. 버튼은 없다(요청자 결정 T1). 까닭마다의 안내 문구는 4절 부모 화면 'AI 쉬는 중' 행을 따른다(컨트롤러 결정 C29) |
| 아이 화면 | 버튼이 없다. '오늘은 끝' 같은 말을 쓰지 않는다. 홈 · 수업 목록의 표시는 4절을 따른다 |
| 들어가는 때 이미 보낸 요청 | 쉬는 상태가 되기 전에 보낸 요청(흐르는 회화 턴, 응답 뒤의 첨삭)은 끝까지 받아 쓰고 기록한다. 하루 안전 상한은 호출을 보내기 전에 그날 호출 수 · 비용 합계로 판정하고, 비용 상한을 넘기게 한 호출의 응답도 그대로 쓴다(4회차 B4-02) |
| 목표 턴 뒤의 회화 | 세션은 완료로 둔다. 다음 턴을 보내면 정리 토막(3.3, AI 를 기다리지 않는다)을 하고 카드의 끝인사로 마무리 화면에 간다. 마무리 첫 장(별 · 오늘 얻은 단어)과 셋째 장만 보이고 둘째 장은 건너뛴다. 끝맺음 턴(요약)은 첨삭처럼 기다렸다가, 풀린 뒤 첫 앱 진입 때 응답 뒤에서 부른다(4회차 A4-U-07 · B4-02) |
| 목표 턴 전 '그만하기' | 끝맺음 턴 없이 중단으로 닫고 요약은 남기지 않는다(4회차 B4-02). 목표 턴 전 '홈'은 쉬지 않을 때와 같이 진행으로 남긴다(3.3, 컨트롤러 결정 C34) |

| AI 호출 하나의 실패 · 지연 | 대화형 호출은 타임아웃 10초, 재시도 1회다(앱이 첫 바이트 전 연결 오류에만 한다. SDK 기본 재시도는 끈다, 6.1). 기다리는 동안 4절의 기다림 표시를 보인다. 실패하면 생각 꺼내기는 '이번에는 바로 써 볼까요'를 보이고, 과제의 예시와 시드 힌트를 붙인 초고 화면으로 간다. 말하기 평가는 판정 없이 다음 문항으로 가고 그 활동은 점수에서 뺀다. 쓰기 확인(4~5단계)이 실패하면 확인 없이 넘어가고 그 세션은 점수 없는 세션이 된다. 회화는 아래 '회화 턴 실패' 행을 따른다. 연결 · 서버 오류와 콘솔 한도가 아닌 429 는 'AI 쉬는 중'의 이어진 실패 수에 더한다. 이어진 실패 수는 턴마다 센다. 앱의 1회 다시 부름이 함께 실패해도 하나다(컨트롤러 결정 C18) |
| 다시 보내도 같은 오류 | 400(콘솔 한도가 아닌 것) · 404 · 413 과 모델 은퇴로 실패한 요청은 다시 부르지 않고 'AI 호출 하나의 실패'로 처리하며 이어진 실패 수에 더하지 않는다. 같은 호출 목적에서 이 오류가 한 학습일에 ai.down_after_failures 번 나면 부모 알림 '호출 설정 확인 필요'(호출 목적 · 모델 · 오류 코드)를 그날 한 번 만든다(컨트롤러 결정 C17) |
| 회화 턴 실패 | 토리의 첫 문장을 보내기 전에 연결 오류 · 타임아웃이 나면, 앱이 아이의 같은 말로 한 번 다시 부른다. 그동안 토리 말풍선에 기다림 표시를 보인다. 1~3단계는 다시 실패해도 대화를 끊지 않는다. 토리 반응 자리에 카드의 짧은 칭찬 대사를 보이고 다음 카드 질문을 붙인다. 그 턴은 '말했다'를 세지 않고, 실패는 'AI 쉬는 중'의 이어진 실패 수에 더한다(4회차 A4-28). 4단계부터는 다시 실패하면 토리가 카드의 대사 'Oops, I need a little break!'(4단계는 '나 잠깐 쉬어야 해!'를 함께)를 말한다. 그리고 '여기까지 이야기한 것은 저장했어요. 다음에 이어서 해요'를 보인 뒤 수업 목록으로 간다. 끝맺음 턴은 부르지 않는다. 목표 턴 전이면 세션은 진행으로 남아 이어 할 수 있고, 목표 턴 뒤이면 이미 끝낸 수업이다(3.3). 거절은 같은 모델로 다시 부르지 않는다. Haiku 5.5 거절은 첫 문장을 보내기 전일 때만 Sonnet 5.5 로 한 번 다시 부른다(6.1). 첫 문장 뒤의 거절은 아래처럼 보낸 문장을 두고 턴을 닫는다(4회차 B4-16). 다시 부른 모델도 거절하면 토리는 카드의 안전한 대사를 말하고 대화를 이어 간다. 1~3단계는 카드의 다음 질문을 붙인다. 첫 문장을 보낸 뒤 스트림이 끊기거나, 타임아웃이 나거나, stop_reason 이 refusal 이나 max_tokens 로 끝나면 보낸 문장은 그대로 둔다. 그 턴을 닫는다. 1~3단계는 다음 카드 질문을 붙이고, 다음 턴 힌트는 카드의 그 턴 힌트로 채운다. 4단계부터는 보낸 문장에 물음표로 끝나는 문장이 없으면 앱이 아직 쓰지 않은 가장 앞 카드 질문을 붙여 보이고 읽어 주고, 다음 턴 힌트는 그 카드 질문의 힌트로 채운다(컨트롤러 결정 C19). 보낸 문장에 질문이 있으면 그 턴의 카드 질문 번호를 알 수 없으므로 '힌트' 버튼을 보이지 않는다. 같은 질문을 되풀이하지 않는다. 서버 측 대체 모델 재시도가 스트림 중간에 일어나면 fallback 블록 뒤의 text 블록을 앞 text 블록에 이어 붙여 하나의 JSON 으로 푼다 |
